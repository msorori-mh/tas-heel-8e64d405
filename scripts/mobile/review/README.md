# APK for field review of PR #237

This is a disposable test build, not a Play release. Its separate application ID (`app.studentamkeen.tamkeen.review`) and label allow installation beside the existing Play app, with separate local data. The Google OAuth callback is the already configured production native callback. If Android asks which app to open after Google, choose **تمكين — اختبار 237**.

The application routes/components/styles are unchanged from feature head `7a8c7c7dbfab7ac56b95360ebe035c2a88276074`. The explicit `TAMKEEN_REVIEW_APK=1` build generates the same UI as a bundled TanStack SPA so it can show an unmerged feature without publishing a web server. Normal builds retain the existing SSR configuration. See [TanStack SPA mode](https://tanstack.com/start/latest/docs/framework/react/guide/spa-mode).

The generated debug activity serves bundled UI assets under the existing HTTPS application origin and passes only `/api/` and `/_serverFn/` requests through to the existing authenticated production backend. It does not supply credentials or bypass access checks. Supabase and Google continue to use the existing services. The review variant suppresses web service-worker updates to keep the packaged source fixed. It reuses the existing hash-verified native offline entry for a cold start without a network. There is no database migration or staging dependency.

The workflow builds and verifies an APK (not an AAB), records source/asset hashes, checks signing and package identity, installs on an Android emulator, loads Google entry, checks an unauthenticated offline-manifest request remains rejected by the existing API, and opens the original native offline entry. Physical login, download and reading are the user's field-acceptance step; automated launch checks are not proof of a completed Google login on their phone. The locally bundled test UI changes startup delivery, so performance timings are not a benchmark of the currently published remote-shell APK.

Only the final APK is for the user. Do not merge this packaging branch into main or upload it to Play. Feature PR #237 remains separately reviewable and unmerged pending field approval. No production signing key is used. On acceptance, publish the approved web change and produce a normal signed Play bundle through the existing release workflow.
