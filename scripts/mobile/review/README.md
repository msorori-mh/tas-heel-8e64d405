# Installation and validation

This is a test build, not a Play release. Earlier `review.direct` builds used an ephemeral debug key because their signing-cache path was absent. The new ID avoids an incompatible update or a request to uninstall that old app. Gradle and the workflow now use the same explicit review-only signing path. The Google OAuth callback is the already configured production native callback. If Android asks which app to open after Google, choose **تمكين — أوفلاين**.

The student layout/components/styles remain those of feature head `7a8c7c7dbfab7ac56b95360ebe035c2a88276074`. PR #241 combines the Settings workflow with #239 client retry/query changes. Server capacity changes are present in the source branch but are not deployed on the backend used by this APK; `review-build.json` explicitly records `backendCapacityApplied: false`. The explicit `TAMKEEN_REVIEW_APK=1` build generates the same UI as a bundled TanStack SPA so it can show an unmerged feature without publishing a web server. Normal builds retain the existing SSR configuration. See [TanStack SPA mode](https://tanstack.com/start/latest/docs/framework/react/guide/spa-mode).

The shared native activity serves bundled UI assets under the existing HTTPS application origin and passes only `/api/` and `/_serverFn/` requests through to the existing authenticated production backend. It does not supply credentials or bypass access checks. Supabase and Google continue to use the existing services. Native builds suppress web service-worker updates to keep the packaged source fixed. Cold start and legacy recovery URLs open the normal application routes using verified local content. There is no database migration or staging dependency.

The workflow captures the visible Google-entry screen inside instrumentation after verifying the foreground package and WebView draw completion. It verifies APK hashes, signing and package identity, API authorization, session restore, native pinch, and the real bundled offline home/subjects/lesson/questions/lab journey. A separate invocation after force-stop and package replacement verifies persisted packs and answers without reseeding. This proves same-signature updates, not migration from a differently signed historical package. Physical login, download and reading remain field-acceptance checks; automated launch checks do not prove a completed Google login on the user's phone.

Only the final APK is for the user. Do not merge this packaging branch into main or upload it to Play. Feature PR #237 remains separately reviewable and unmerged pending field approval. No production signing key is used. On acceptance, publish the approved web change and produce a normal signed Play bundle through the existing release workflow.
