# الخطة **معتمدة للتنفيذ** مع تصحيحين فقط:

```text
CONTENT_IMPORT_OPERATIONAL_E2E_07 = GO
NON_PROD_ONLY = YES
PRODUCTION = FORBIDDEN

```

الأول: لا يمكن إثبات `BLOCKED_PUBLISHED` بدون وجود عنصر منشور. لذلك أسمح **فقط داخل Non-Prod** بانتقال عنصر تجريبي معزول يحمل بادئة `e2e-` عبر مسار المراجعة/النشر المعتمد إلى `published`، حصراً لاختبار الحاجز. هذا لا يُعد إطلاق محتوى ولا Publish إنتاجياً.

الثاني: **لا أنصح بإنشاء Migration تنظيف دائمة**؛ ستلوث سجل الـmigrations بعملية خاصة بالاختبار. التنظيف يكون عبر مسار الحذف الإداري/RPC الموجود إن كان يغطي الكيانات. وإذا لم يوجد مسار آمن، نستخدم teardown غير إنتاجي محروس ومحصور حصراً في `e2e-*`، ولا يدخل `supabase/migrations/`.

وأضيف تحققاً إلزامياً مهماً لطرف الطالب:

```text
draft/pending content:
- hidden from lists
- hidden from search/navigation
- direct-by-id access denied/not returned
- underlying API/RPC does not leak it

```

وبالنسبة للقالب 09، النتيجة الصحيحة تبقى:

```text
09 = SAFE_BLOCKED
ERROR = QUESTION_BANK_WORKFLOW_REQUIRED
ZERO QUESTION DOMAIN WRITES

```

بوابة النجاح النهائية:

```text
01–08 initial import        PASS
01–08 exact replay          PASS / all skipped
invalid file                PASS / zero writes
published mutation attempt  PASS / BLOCKED_PUBLISHED
student draft visibility    PASS / zero exposure
09 question template        PASS_AS_SAFE_BLOCKED
cleanup                     PASS
ZERO CRITICAL/HIGH
= CONTENT_IMPORT_OPERATIONAL_E2E_07_PASS

```

إذا خرج `07_PASS` يصبح **استيراد المحتوى 01–08 جاهزاً تشغيلياً على Non-Prod**، وتنتقل الأولوية مباشرة إلى إغلاق **قالب الأسئلة 09 وربطه ببنك الأسئلة**؛ وهذا هو آخر حاجز رئيسي قبل أن نقول إن «استيراد المحتوى والأسئلة» جاهز كوحدة واحدة.CONTENT_IMPORT_OPERATIONAL_E2E_07 — تشغيل فعلي على Non-Prod

الهدف: إثبات أن مسار استيراد المحتوى (قوالب 01–08) يعمل تشغيلياً من طرف المشغّل الحقيقي، وأن سلوكه مطابق للعقد في حالات النجاح والفشل والإعادة. لا Publish ولا Production ضمن هذه المرحلة.

## 1. ملفات الاختبار (Fixtures)

توليد حزمة ملفات Excel واقعية تحت `tests/e2e/content-import/fixtures/` عبر سكربت `scripts/content-import/generate-e2e-fixtures.mjs`:

- حزمة صحيحة لكل قالب 01–08 (مادة/وحدة/درس/شرح/مورد/ملخّص/تقييم/ربط تقييم) مترابطة عبر الأكواد النصية، بأكواد مسبوقة بـ `e2e-` لعزلها.
- ملف خاطئ واحد (عمود أساسي ناقص + مرجع كود غير موجود) لإثبات صفر كتابة.
- ملف "تعديل على محتوى منشور" لإثبات `BLOCKED_PUBLISHED`.
- ملف قالب 09 (أسئلة) لإثبات الرفض الآمن.

## 2. سيناريو التشغيل الفعلي

يُنفَّذ من واجهة `/admin/import` بحساب طاقم محتوى فعلي (تشغيل آلي عبر متصفح على بيئة المعاينة)، خطوة بخطوة لكل قالب بالترتيب 01 → 08:

```text
Validate  → يجب أن ينجح بلا أخطاء
Prepare   → صفوف Staging = عدد صفوف الملف
Execute   → inserted = N ، updated = 0 ، blocked = 0
```

بعد كل قالب: قراءة حالة المراجعة من قاعدة البيانات والتأكد أن المحتوى الجديد `review_status = pending` و`publication_status = draft`.

### إعادة رفع نفس الملف (Idempotency)

إعادة الدورة الكاملة بنفس الملف لكل قالب، والتحقق:

```text
same file → inserted = 0 ، updated = 0 ، skipped = N
```

### حالة الملف الخاطئ

Validate يفشل، ولا يُسمح بالتجهيز. التحقق بعدها من قاعدة البيانات أن عدد صفوف النطاقات المعنية لم يتغير إطلاقاً (zero domain writes) وأن صفوف Staging لم تُنشأ.

### حالة المحتوى المنشور

تحويل عنصر واحد من عناصر الاختبار إلى منشور عبر مسار المراجعة المعتمد (بدون نشر أي محتوى حقيقي)، ثم محاولة تعديله بالاستيراد. المتوقّع: العنصر يُحتسب ضمن `blockedPublished` ولا يتغيّر محتواه في قاعدة البيانات.

### قالب 09

محاولة التجهيز يجب أن تُرفض برسالة `QUESTION_BANK_WORKFLOW_REQUIRED` — تُوثَّق كـ `SAFE_BLOCKED` لا كإخفاق.

## 3. التحقق من طرف الطالب

بحساب طالب مطابق للصف والمنهج المستهدف: التأكد أن أي محتوى مستورد بحالة مسودة/قيد مراجعة **لا يظهر** في قوائم المواد والدروس ولا عبر الوصول المباشر بالمعرّف.

## 4. التنظيف

حذف بيانات الاختبار المعزولة (`e2e-*`) في نهاية التشغيل عبر ترحيل تنظيف مخصص، مع إبقاء سجلات `import_jobs` للمراجعة.

## 5. المخرجات

- `docs/import/CONTENT-IMPORT-OPERATIONAL-E2E-07.md`: مصفوفة النتائج (قالب × سيناريو × PASS/FAIL) مع الأرقام الفعلية لكل تنفيذ ولقطات الحالة.
- تسجيل الحكم النهائي: `07_PASS` أو قائمة المانعين.

## تفاصيل تقنية

- التحقق من قاعدة البيانات يتم بقراءات SELECT فقط (`import_jobs`, `import_staging_rows`, `content_review_state`, وجداول المحتوى) — لا كتابة مباشرة خارج مسار RPC المعتمد.
- التشغيل الآلي للمتصفح يستخدم جلسة المعاينة المحقونة؛ إن لم تتوفر جلسة طاقم محتوى، يتوقف التنفيذ ويُطلب تسجيل الدخول من المعاينة بدل تجاوز البوابة.
- لا تُنشأ أي دالة أو ترحيل جديد لتسهيل الاختبار سوى ترحيل التنظيف النهائي.
- بيئة التنفيذ هي Non-Prod حصراً؛ لا نشر ولا لمس للإنتاج.
