# الخطة جيدة، وأعتمدها مع قرار واضح بخصوص الملاحظة الأخيرة:

```text
CURRICULUM_CONTENT_ENTRY_READINESS_13 = GO
CONTENT_ENTRY_GROUP_IMPORT_BINDING_13A = REQUIRED
CONTENT_ENTRY_OPERATOR_READY = NOT YET FINAL

```

السبب: وجود `group_code/group_name` في قاعدة البيانات والواجهة والقالب **لا يكفي** إذا كان `import_execute_template` لا يحفظهما فعلياً. تسليم النظام ليوسف بهذه الحالة سيخلق فجوة خطيرة: Template 01 يمر Validate لكن التنفيذ قد يتجاهل التجميع.

هناك 3 نقاط أريد تثبيتها قبل الإغلاق:

1. تحقق المجموعة يجب أن يكون على مستويين:
  - داخل الملف نفسه: نفس `(grade, track, group_code)` ⇒ نفس `group_name`.
  - مقابل البيانات الموجودة في DB عند Execute أيضاً، وليس فقط في TypeScript. أي تعارض مع مادة موجودة يجب أن يكون Fail-closed.
2. مصفوفة صلاحيات يوسف تُثبت باختبار صلاحية حقيقي، خصوصاً Template 09. لا نفترض أن `content_manager` يملك تلقائياً `can_edit_question_bank`. المطلوب:
  ```text
  content_manager + required QB edit capability → 09 Draft Import PASS
  content_manager بدون capability المطلوبة     → DENIED

  ```
  وإذا احتاج Capability منفصلة، نوثقها في Runbook بدلاً من توسيع الدور كله.
3. راجع Trigger تثبيت `group_code` الحالي. إذا كان يمنع تغييره بمجرد إنشائه، فلا تكتب في الدليل أن المستخدم يستطيع تعيينه لاحقاً عندما يكون NULL إلا إذا أثبت الاختبار أن الانتقال:
  ```text
  NULL → قيمة

  ```
  مسموح فعلاً في DB.

## القرار بشأن الـMigration المعلقة

**لا أوافق على تركها معلقة عند تسليم النظام ليوسف.**

افصلها كمرحلة صغيرة:

```text
CONTENT_ENTRY_GROUP_IMPORT_BINDING_13A

```

ونطاقها فقط إعادة تعريف `import_execute_template` لدعم `group_code/group_name`، بدون أي Curriculum Data.

قبل تطبيقها على قاعدة Lovable المشتركة يجب إثبات:

```text
Migration changes function logic only
No destructive schema changes
No RLS weakening
No new anon/authenticated grants
SECURITY DEFINER preserved
search_path fixed
group fields optional
non-grouped subjects unchanged
group consistency fail-closed
template 01 idempotency preserved
templates 02–09 unaffected
tests/typecheck/build PASS

```

إذا تحققت هذه الشروط، **أعتمد تطبيق 13A على القاعدة المشتركة** ثم Post-Apply verification، دون الحاجة للعودة إليّ لموافقة إضافية ضمن هذه السلسلة.

بعدها فقط يكون الحكم:

```text
SUBJECT_AS_BRANCH OPERATIONAL          PASS
GROUP IMPORT EXECUTION                 PASS
DIRECT DELETE BYPASS                   ZERO
CONTENT_MANAGER MATRIX                 VERIFIED
IMPORT CENTER LEGACY UX                CLOSED
OFFICIAL OPERATOR PACK                 COMPLETE
TESTS / TYPECHECK / BUILD              PASS
CURRICULUM DATA WRITES                 ZERO

CONTENT_ENTRY_OPERATOR_READY = YES

```

وبعد `YES` نعتبر **بنية إدخال المحتوى منتهية** ونتوقف عن إضافة وظائف جديدة لها؛ يوسف يبدأ لاحقاً من قاعدة نظيفة بالقوالب الرسمية، دون أي مادة تجريبية أو Pilot وهمي.        تابع تنفيذ CURRICULUM_CONTENT_ENTRY_READINESS_13 في جميع الأعمال غير الإنتاجية، ولا تنشئ أي مادة أو ملفات محتوى تجريبية ولا تكتب Curriculum Data.

لكن لا تعتبر CONTENT_ENTRY_OPERATOR_READY = YES بعد، لأن migration:

supabase/migrations-pending/20260814020000_content_entry_readiness_13.sql

ما زالت غير مطبقة، وهي مطلوبة لجعل group_code/group_name يعملان فعلياً داخل import_execute_template.

أكمل الآن:

- اختبارات الصلاحيات

- direct delete bypass = zero

- content_manager matrix

- Import Center cleanup

- template/order guards

- docs/runbook

- typecheck/build/tests

ثم توقف عند بوابة:

CONTENT_ENTRY_READINESS_13_CODE_READY

وأعطني مراجعة دقيقة للـ migration المعلقة:

1. ما الذي تغيره بالضبط في import_execute_template.

2. هل هي additive/non-destructive.

3. هل تغيّر RLS/GRANT أو أي صلاحيات.

4. هل تحافظ على idempotency للقالب 01.

5. هل group_code/group_name اختياريان للمواد غير المتفرعة.

6. هل تمنع اختلاف group_name لنفس (grade, track, group_code).

7. هل تؤثر على القوالب 02–09.

8. نتيجة rehearsal/tests قبل التطبيق.

لا تطبق migration على قاعدة Lovable المشتركة في هذه الخطوة.

لا تنشئ أي بيانات منهج.CURRICULUM_CONTENT_ENTRY_READINESS_13 — إغلاق تشغيلي مع الضوابط الخمسة

القيود: لا كتابة على بيانات المنهج، لا إدخال محتوى إنتاجي، لا بيانات وهمية. الاختبارات تعتمد fixtures / تحليل كود فقط.

## 1. SUBJECT_AS_BRANCH — إتمام القواعد

- عقد Template 01 والقالب وواجهة CRUD يحملون `group_code` و `group_name` (اختياريان).
- قواعد التعديل في واجهة المادة:
  - `subject_code`: يُحدد عند الإنشاء فقط، غير قابل للتعديل بعدها.
  - `group_code`: يُسمح بتعيينه لاحقاً فقط عندما يكون فارغاً؛ بعد أن تصبح المادة مستخدمة (وحدات/دروس/أسئلة/نشاط) يُقفل في الواجهة.
  - `group_name`: تسمية عرض قابلة للتعديل دائماً.
- تحقق تناسق: نفس الصف + نفس المسار + نفس `group_code` ⇒ نفس `group_name` (تحقق في العقد/الاستيراد وفي حوار التحرير).
- حارس دلالي: `group_code` لا يظهر في أي مسار صلاحيات (RLS، `can_access_subject`، `question_targets`).

ملاحظة قائمة حالياً: قفل `group_code` بعد التعيين مطبّق على مستوى قاعدة البيانات (trigger موجود مسبقاً)، فالقفل «بعد الاستخدام» يُطبّق كطبقة واجهة فوقه — بدون ترحيل جديد.

## 2. إغلاق مسارات الحذف المباشرة

- التأكد أن حوارات الحذف القديمة للمواد/الوحدات/الدروس لم تعد موجودة، والمسار الوحيد:
معاينة RPC ← عرض الأثر والموانع ← Full Admin فقط ← `admin_curriculum_delete` ← سجل تدقيق.
- `content_manager`: معاينة نعم، حذف نهائي لا (حتى لو رأى الحوار).
- اختبار ثابت يفحص كود لوحة الإدارة ويثبت: عدد مسارات الحذف المباشر على جداول المنهج = 0.

## 3. مصفوفة صلاحيات المشغّل (يوسف)

توثيق واختبار للمصفوفة:

- 01–07 إنشاء/تعديل/استيراد: مسموح
- Validate / Prepare / Execute: مسموح
- 09 استيراد أسئلة كمسودات: مسموح
- حذف نهائي / إدارة مستخدمين وأمان / نشر بنك الأسئلة / نشر المحتوى: ممنوع بدون صلاحية منفصلة
- سير العمل الرسمي: يوسف 01→07→09 ← مراجع ← ناشر ← يوسف 08.

## 4. مركز الاستيراد = صفحة تشغيل

- إزالة أي بقايا: POC المحافظات، «قريباً»، «التنفيذ لاحقاً»، «تفاصيل الأخطاء لاحقاً».
- شريط ترتيب واضح أعلى الصفحة: 01→02→03→04→05→06→07→09→Review→Publish→08، مُشتق من `IMPORT_EXECUTION_ORDER` فقط (مصدر واحد للقائمة المنسدلة والنص).
- سجل العمليات بأعمدة: القالب، الملف، الصفوف، مُدرج، مُحدّث، متجاوَز، محجوب، أخطاء، الحالة، المشغّل، التاريخ. المشغّل يُشتق من `created_by` الحقيقي في `import_jobs` (اسم من الملف الشخصي عند توفره، وإلا معرّف مختصر) — بدون أي قيمة وهمية.

## 5. حزمة يوسف الرسمية

- مجلد حزمة واحد يجمع القوالب التسعة + `NAMING-CONVENTION` + `DATA-DICTIONARY-AR` + `CONTENT-OPERATOR-GUIDE-AR`.
- الدليل يتضمن مثالين صريحين: مادة ← وحدة ← درس، ومادة ← درس مباشرة، ومثال مواد متفرعة (مجموعة «اللغة العربية»: النحو والصرف، البلاغة، الأدب) مع تنبيه أن المجموعة ليست مستوى صلاحية ولا Question Target.

## ملاحظة واحدة تحتاج قرارك

دعم `group_code/group_name` داخل تنفيذ الاستيراد على مستوى الخادم يحتاج تحديث دالة `import_execute_template`؛ الملف جاهز غير مطبّق في `supabase/migrations-pending/`. التزاماً بـ NEW MIGRATION = NOT EXPECTED سيبقى معلقاً في هذه المرحلة، ويُنفَّذ الجزء الواجهي والعقد فقط، ويُدرج التطبيق كخطوة مستقلة لاحقة.
