# الخطة جيدة، لكن **أعتمد المسار A بالكامل، والمسار B مع بعض الضوابط حتى لا يتحول** `Subject-as-Branch` **إلى مشكلة في الاشتراكات أو التقارير لاحقاً**.

```text
FIRST_REAL_CONTENT_BATCH_12 = GO_TO_PREVIEW
MULTI_BRANCH_ARCHITECTURE_12B = APPROVED_WITH_GUARDS

```

### A) أول دفعة حقيقية

نستطيع الاستمرار الآن بمادة بسيطة غير متفرعة:

```text
01 Subject
→ 02 Unit
→ 03 Lesson
→ 04 Book Content
→ 05 Explanation
→ 06 Resources
→ 07 Assessment

```

بدون أسئلة وبدون نشر.

وبوابة Preview تبقى:

```text
INSERT  > 0
UPDATE  = 0
SKIP    = 0
BLOCKED = 0

```

---

## B) قرار المواد متعددة الفروع

أوافق على **Subject-as-Branch** بدلاً من إنشاء `subject_branches`.

مثال:

```text
اللغة العربية
├─ arabic-nahw-grade-12-sanaa
├─ arabic-balagha-grade-12-sanaa
├─ arabic-adab-grade-12-sanaa
└─ arabic-reading-grade-12-sanaa

```

كل فرع يصبح Subject كاملاً وله:

```text
Units
Lessons
Content
Assessments
Questions
Progress

```

وهذا يحافظ على كل ما أنجزناه في الاستيراد وبنك الأسئلة.

### لكن `group_code` له قاعدة مهمة

لا نستخدم:

```text
group_code = arabic

```

كهوية مستقلة عالمية.

التجميع الحقيقي يجب أن يكون ضمن:

```text
grade
+ curriculum_track
+ group_code

```

أي مثلاً:

```text
grade-12 + sanaa + arabic

```

حتى لا تختلط العربية للصف العاشر مع الثاني عشر أو مسار صنعاء مع عدن.

ويمكن أن تكون الحقول:

```text
subjects.group_code   nullable
subjects.group_name   nullable

```

مثل:

```text
group_code = arabic
group_name = اللغة العربية

```

لكن يجب أن يفرض Validate:

```text
نفس grade + track + group_code
→ نفس group_name

```

وإلا يرفض الملف.

### مهم جداً: `group_code` ليس صلاحية

لا يجوز استخدامه مباشرة في:

```text
RLS
can_access_subject
question_targets
assessment binding

```

هذه تبقى مبنية على `subject_id`.

`group_code` يكون في المرحلة الأولى فقط:

```text
UI grouping
navigation
report aggregation

```

## نقطة تجارية يجب مراقبتها

هناك حالة واحدة يجب ألا ننساها:

إذا كان المستخدم يشتري مستقبلاً **«اللغة العربية كاملة»** وليس كل فرع منفصلاً، فلا نريد أن تتحول:

```text
النحو
البلاغة
الأدب
القراءة

```

إلى أربع اشتراكات منفصلة بسبب كونها أربع Subjects.

لذلك قبل أي تسعير حسب المادة، نحتاج قاعدة:

```text
Entitlement may cover:
single subject
OR subject group

```

لكن **لا نحتاج حلها الآن لبدء استيراد المحتوى**.

## تعديل صغير على توصية Lovable

هذه العبارة:

> نعيد النظر في Branch حقيقي إذا ظهر امتحان وزاري واحد يخلط الفروع.

ليست بالضرورة صحيحة.

يمكن أن يكون الامتحان الواحد ببساطة:

```text
Exam Template
├─ questions from Arabic/Nahw
├─ questions from Arabic/Balagha
├─ questions from Arabic/Adab
└─ questions from Arabic/Reading

```

دون الحاجة إلى جدول Branch.

وكذلك الدرجة المجمعة يمكن حسابها عبر `group_code`.

إذن جدول `subject_branches` لا نضيفه إلا إذا ظهر **سلوك فعلي لا يمكن تمثيله بمجموعة Subjects**، وليس لمجرد وجود امتحان أو درجة مشتركة.

## ما أنصح به الآن

نثبت 12B وثائقياً:

```text
ARCHITECTURE:
SUBJECT_AS_BRANCH

GROUPING:
(grade, curriculum_track, group_code)

group_code:
optional

legacy subject hierarchy:
unchanged

```

ثم **لا ننفذ Migration** `group_code/group_name` **الآن إذا كانت أول دفعة فيزياء أو رياضيات**؛ ليست مطلوبة للـPilot.

بعد إثبات `FIRST_REAL_CONTENT_BATCH_12 = PASS` ننفذ التغيير الصغير الخاص بالتجميع، ونختبر مادة مثل العربية قبل رفعها على نطاق واسع.

الحالة:

```text
Import Engine                     ✅ COMPLETE
Official Templates                ✅ READY
Simple Subject Import             ✅ READY
Subject-as-Branch Architecture    ✅ APPROVED
Grouping Fields                   ⏳ BEFORE FIRST BRANCHED SUBJECT
First Real Pilot                  🟢 NEXT
Arabic / Islamic Studies          🟡 AFTER GROUPING SUPPORT

```

**إذن الآن لا يوجد سبب لتأخير أول Pilot.** الخطوة العملية التالية هي اختيار ملفات مادة بسيطة حقيقية وإدخالها حتى Preview فقط.12A مُعتمد — المساران A و B

## A) FIRST_REAL_CONTENT_BATCH_12 — جاهز حتى Preview

المسار التشغيلي كما اعتمدته: مادة بسيطة واحدة (فيزياء/رياضيات/أحياء)، القوالب 01→07 فقط، بلا 09 و08 وبلا نشر تلقائي.
الأكواد تأتي حصراً من ملفاتك. لا Prepare ولا Execute قبل عرض Preview يقرأ: INSERT > 0، UPDATE = 0، SKIP = 0، BLOCKED = 0.

الخطوة المطلوبة منك: رفع ملفات الدفعة (01–07). بعدها أُصدر تقرير Preview Gate.

## B) MULTI_BRANCH_SUBJECT_ARCHITECTURE_REVIEW_12B — الجواب المعماري النهائي

### ما هو موجود فعلاً في القاعدة (تم فحصه الآن)

- `units.subject_id` إلزامي، ولا يوجد `parent_id` في `units` — أي لا تداخل بين الوحدات.
- `lessons.unit_id` قابل للفراغ (NULL) و`lessons.subject_id` إلزامي.
- لا يوجد أي مستوى Branch في الـ schema ولا في العقد (`import-contract.ts`).

النتيجة: الهيكل الحالي يدعم أصلاً احتمالين من الأربعة:

```text
Subject → Unit → Lesson      مدعوم
Subject → Lesson             مدعوم (unit_id = NULL)
Subject → Branch → Unit → Lesson    غير مدعوم
Subject → Branch → Lesson           غير مدعوم
```

### هل المناهج الحقيقية تحتاج مستوى Branch مستقل؟

منطقياً نعم — عملياً لا نحتاج جدولاً جديداً.

اللغة العربية في الثانوية اليمنية تُدرَّس ككتب/فروع منفصلة (النحو والصرف، البلاغة، الأدب والنصوص، المطالعة والإملاء)، ولكل فرع وحداته ودروسه وتقييمه، وقد تختلف حصصه ودرجاته. والتربية الإسلامية كذلك (القرآن والتلاوة، التفسير، الحديث، الفقه، العقيدة). فالفرع ليس تسمية شكلية بل حاوية تعليمية كاملة.

**التوصية النهائية: لا نضيف جدول `subject_branches`، بل نمثّل كل فرع كـ Subject مستقل** بكود صريح، ونضيف حقل تجميع اختياري فقط للعرض:

```text
arabic-nahw-grade-12-sanaa      → المادة: اللغة العربية — النحو والصرف
arabic-balagha-grade-12-sanaa   → اللغة العربية — البلاغة
islamic-fiqh-grade-12-sanaa     → التربية الإسلامية — الفقه
```

الأسباب:

1. كل منطق المنصة مربوط بالمادة: RLS، `can_access_subject`، `user_progress`، الاشتراك، قوالب الامتحانات، وربط `question_targets`. إدخال مستوى رابع يعني إعادة فتح كل ذلك بعد أن أُغلق في 11A و12A.
2. الفرع يحمل نفس خصائص المادة تماماً (صف + مسار منهج + وحدات + دروس + تقييمات)، فهو Subject بحكم البنية.
3. نظام الاستيراد كله (العقد، الأكواد الطبيعية، `subject_code` في 04–07، اشتقاق الـ slug) يبقى كما هو دون أي تعديل — صفر ارتداد على 12A.

ما نضيفه في 12B لاحقاً (تغيير صغير ومعزول، عرض فقط):

- عمودان اختياريان على `subjects`: `group_code` و`group_name` (مثال: `arabic`, «اللغة العربية»).
- عمود اختياري مقابل في القالب 01 فقط.
- تجميع بصري في واجهة الطالب: بطاقة «اللغة العربية» تفتح على فروعها.

لا تغيير في RLS، ولا في الوحدات والدروس، ولا في مسار الأسئلة.

### متى نعيد النظر في جدول Branch حقيقي؟

فقط إذا ظهر أحد هذه الشروط: اشتراك/تسعير على مستوى الفرع، أو درجة مجمّعة إلزامية عبر الفروع، أو امتحان وزاري واحد يخلط فروعاً بأوزان محددة. حتى ذلك الحين، Subject-as-Branch كافٍ ومطابق للواقع.
