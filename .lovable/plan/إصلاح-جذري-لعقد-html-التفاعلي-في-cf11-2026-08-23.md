# إصلاح جذري لعقد HTML التفاعلي في CF11

## التشخيص المؤكد
- مسار الاستيراد الحالي يصنّف `mindMapHtml` و`labExperimentHtml` كمحتوى تفاعلي ويسمح بـ JavaScript.
- مرحلة CF11 ما زالت تصنّف `mindMapHtml` كمحتوى ثابت وتستدعي `cf11_assert_static_contract`، لذلك ترفض الملف لاحقاً بعد أن قبلته المراحل السابقة.
- ملفا الدرس الحاليان للخريطة والتجربة يحتويان سكربتات ومعالجات أحداث، ولا يحتويان CSP داخلياً، ولا يحتويان روابط شبكة أو سكربتات خارجية أو `eval`.
- عارض الطالب يعزل المحتوى فعلياً داخل iframe بلا `allow-same-origin` وبصلاحية `allow-scripts` فقط، ويضيف CSP يمنع الشبكة والنوافذ والنماذج والإطارات الخارجية.

## التنفيذ
1. **توحيد العقدة القانونية للمحتوى**
   - اعتماد `mindMapHtml` و`labExperimentHtml` كمحتوى `INTERACTIVE` في الاستيراد، CF11، بيانات المورد، وخطة النشر.
   - إزالة أي افتراض متبقٍ بأن الخريطة ثابتة أو خالية من JavaScript.

2. **فصل عقد الملف عن عقد بيئة التشغيل**
   - تعديل فاحص CF11 التفاعلي ليقبل ملفات HTML الحالية كما هي دون اشتراط CSP أو علامة sandbox داخل الملف نفسه.
   - الإبقاء على الرفض الصارم للاتصال الخارجي، السكربتات الخارجية، `eval`/`Function`، العناصر الخطرة، وتسريب الإجابات.
   - اعتبار iframe المعزول وCSP اللذين يضيفهما عارض الطالب هما حاجز التشغيل الأمني المعتمد، بدلاً من مطالبة كل ملف مؤلف بتكرار هذا الحاجز داخله.

3. **تصحيح النشر والبيانات الناتجة**
   - تمرير الخريطة والتجربة عبر نفس فاحص المحتوى التفاعلي.
   - حفظ `html_resource_type = INTERACTIVE` و`cf11_render_mode = INTERACTIVE` لكليهما.
   - تسجيل عقد التشغيل الأمني في metadata وخطة DRY RUN لكلا الموردين، لا للتجربة فقط.

4. **ترحيل آمن وقابل لإعادة التطبيق**
   - إنشاء migration جديدة تعدّل الدوال الحية دون تغيير بيانات الحزمة أو بصماتها.
   - تضمين حراس تفشل بوضوح إذا تغير شكل دالة CF11 المتوقع، بدلاً من تطبيق استبدال نصي صامت أو جزئي.
   - تحديث ملف CF11 المرجعي المعلّق حتى لا تعيد ترقية مستقبلية العقد القديم.

5. **اختبارات تمنع تكرار المشكلة**
   - اختبار قبول خريطة تفاعلية ذات `<script>` و`onclick` دون CSP داخلي عندما تكون ذاتية الاحتواء.
   - اختبار رفض URL شبكي، سكربت خارجي، `eval`، وتسريب الإجابات في الخريطة والتجربة.
   - تحديث اختبار CF11 القديم الذي يطالب بأن تكون الخريطة خالية تماماً من JavaScript.
   - إضافة اختبار تطابق يثبت أن تصنيف كل capability واحد في: TypeScript، SQL، metadata، وخطة النشر.

6. **تحقق نهائي على الحالة الفعلية**
   - تشغيل DRY RUN على batch الحالي للدرس `lesson-g12-012-001` والتأكد من تجاوزه CF11 دون كتابة.
   - تنفيذ النشر الفعلي ثم التحقق من إنشاء الموردين كـ `INTERACTIVE` ومن تشغيلهما في عارض الطالب المعزول بلا طلبات شبكة أو أخطاء console.

## النتيجة المتوقعة
لن تقبل مرحلة ملفاً باعتباره تفاعلياً ثم ترفضه مرحلة لاحقة باعتباره ثابتاً. ملفات الخريطة والتجربة الحالية تُنشر كما هي، بينما يبقى التنفيذ محصوراً داخل sandbox وCSP يفرضهما التطبيق مركزياً.
