# CONTENT_AND_QUESTION_UNIFIED_OPERATIONAL_E2E_09

اختبار حزمة الاستيراد كاملة (01→09) كوحدة واحدة على مادة/درس تجريبي، وفق Dependency Graph الحقيقي، دون بناء أي بنية جديدة.

## ما سيُنفَّذ

مشغل واحد جديد `tests/e2e/content-import/run-unified-import-e2e-09.ts` يشغّل الحزمة بالترتيب التبعي الصحيح في جلسة موظف حقيقية (JWT + RLS)، ثم يتحقق من الحالة النهائية للمحتوى والأسئلة ومن رؤية الطالب.

مراحل التشغيل داخل المشغّل:

```text
Pass 1  رفع الحزمة 01→09 كاملة لأول مرة
Pass 2  إعادة نفس الحزمة بالكامل            ⇒ Idempotency
Pass 3  تعديل جزئي (درس + سؤال)             ⇒ Update / New Draft Revision فقط
Pass 4  سؤال موجود + Target جديد            ⇒ TARGET_ADDED بلا نسخة جديدة
Pass 5  حقن ملف فاسد داخل الحزمة            ⇒ فشل معزول، بقية المنظومة سليمة
Pass 6  فحوصات الطالب + حالة المراجعة
Pass 7  Teardown كامل لبيانات e2e-*
```

## حالات التحقق (Exit Gate)

| # | التحقق |
| --- | --- |
| 1 | ترتيب التبعية يُحترم: مادة ← وحدة ← درس ← محتوى/شرح/موارد ← تقييم ← ربط ← أسئلة |
| 2 | الحزمة الأولى: كل قالب inserted بالعدد المتوقع، بلا أخطاء |
| 3 | الإعادة: 0 inserted / 0 updated لكل القوالب (Idempotency على مستوى الحزمة لا الملف) |
| 4 | التعديل الجزئي: الملفات غير المعدّلة تبقى skipped، والمعدّل فقط updated |
| 5 | سؤال موجود بوجهة جديدة: نسخة المحتوى نفسها + صف وجهة إضافي |
| 6 | ملف فاسد داخل الحزمة: تراجع ذرّي لذلك القالب فقط، والقوالب السابقة تبقى صحيحة، ولا صفوف staging عالقة |
| 7 | حالة المراجعة (content_review_state) مضبوطة للكيانات الجديدة وتُعاد ضبطها عند تغيّر البصمة |
| 8 | الطالب لا يرى الدرس/المادة غير المنشورة عبر RPCs المحتوى |
| 9 | الطالب لا يرى الأسئلة المسودة، ولا الخيارات، ولا الإجابة الصحيحة (تسريب = صفر) |
| 10 | لا نشر تلقائي: `current_published_revision_id` يبقى فارغاً لكل أسئلة الحزمة |
| 11 | التنظيف: لا صف `e2e-*` متبقٍّ، وعدّادات النطاقات تعود لخط الأساس |

## عدم الانحدار (Regression)

بعد نجاح المشغّل الموحّد تُعاد الحزم الحالية كما هي دون تعديل:

- `run-content-import-e2e-07.ts` (32)
- `run-question-import-e2e-08.ts` (18)
- `npm run test:import-contract` (60)
- `npm run test:question-bank-import`

النتيجة النهائية تُعتبر PASS فقط إذا نجحت الحزمة الموحّدة والحزم الثلاث السابقة معاً.

## التفاصيل التقنية

- **Fixtures**: توسيع `scripts/content-import/generate-e2e-fixtures.mjs` بحزمة موحّدة بادئتها `u09-` (مادة/وحدة/درسان/محتوى/شرح/موردان/تقييم/ربط/ثلاثة أسئلة) + نسخة معدّلة جزئياً + نسخة وجهة جديدة + ملف فاسد واحد. البادئة تبقى ضمن `e2e-` ليعمل الـ teardown القائم.
- **مسار التنفيذ**: يُعاد استخدام `runCycle` (validate → `createContentImportExecutionJob` → `stageContentImportRows` → `executeContentImport`) بلا أي تعديل على كود الإنتاج؛ المشغّل الموحّد يستدعي نفس الدوال المستخدمة في لوحة الإدارة.
- **الطالب**: جلسة طالب حقيقية عبر `E2E_STUDENT_USER_ID` (اختياري؛ إذا لم يُضبط تُسجَّل الحالات كـ skipped صراحةً بدل PASS صامت).
- **التنظيف**: `purgeE2eQuestions` القائم + حذف صفوف النطاقات ببادئة `e2e-` فقط، مع التقاط خط أساس قبل التشغيل ومقارنته بعده.
- **حواجز الأمان**: يرفض التشغيل بدون `RUN_CONTENT_IMPORT_E2E=1`، ولا يكتب أي صف خارج بادئة `e2e-`، ولا يلمس الإنتاج.
- **توثيق**: تقرير إغلاق `docs/unified-import-e2e-09.md` بجدول النتائج وأمر التشغيل.

## خارج النطاق

لا تغييرات على schema، ولا على قواعد RLS، ولا على مسار الاستيراد نفسه — إلا إذا كشف الاختبار خللاً حقيقياً، وعندها يُصلَح الخلل ويُعاد تشغيل الحزم كاملة.
