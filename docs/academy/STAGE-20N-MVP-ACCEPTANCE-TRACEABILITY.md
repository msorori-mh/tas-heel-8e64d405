## 1) قرار البوابة الحالي

بوابة البرمجة الكاملة لأكاديمية معلم الثانوية تبقى **مغلقة** حتى تتحقق الشروط الأربعة معًا:

1. **بنك الأسئلة:** إغلاق اعتماد QB runtime cutover رسميًا؛ PR #58 ما يزال Draft والافتراضي LEGACY.
2. **عقد الاستيراد:** اعتماد V2 رسميًا؛ PR #96 ما يزال Draft/HOLD.
3. **بنية الأكاديمية:** تحويل الصلاحيات من capability عامة على المستخدم إلى صلاحيات Scoped حسب النطاق المعتمد، واستبدال التسجيل المباشر بعقد Entitlement واضح.
4. **الأمن:** إغلاق مانع الحوكمة المرتبط بـ `admin_curriculum_force_delete` قبل أي توسع إنتاجي؛ الدالة تتحقق داخليًا من Full Admin لكنها ما تزال ممنوحة للتنفيذ لدور `authenticated` وتنفذ حذفًا عميقًا لبيانات تعلم/أسئلة/نشر.

لا تعتبر التحسينات التشغيلية في الأسئلة أو الاستيراد بديلًا عن الإغلاق الرسمي للبوابات أعلاه.

## 2) حدود المنتج الملزمة

### Student persona

- تطبيق وواجهة وخدمات الطالب تبقى مستقلة وظيفيًا.
- `public.profiles` و`app_role` واشتراك الطالب لا تمنح أي Capability للأكاديمية.
- لا تُعرض إدارة البرامج أو الشهادات أو العقود أو إعدادات الأكاديمية داخل Student workspace.

### Teacher persona

- الأكاديمية تستخدم `academy.teacher_profiles` وهوية معلم مستقلة عن ملف الطالب.
- يمكن مشاركة طبقة Auth التقنية فقط؛ مشاركة الجلسة لا تعني مشاركة الدور أو الملف أو الاشتراك أو الصلاحيات.
- Teacher workspace له Navigation وUX وAuthorization مستقلان.

### Dual persona

إذا كان المستخدم نفسه طالبًا ومعلمًا:

- يحتفظ بملفين منطقيين منفصلين.
- كل دخول إلى Workspace يحدد Persona صراحة.
- لا يرث أي Entitlement أو Capability بين المساحتين.
- تسجيل الخروج/تعليق حساب إحدى الشخصيتين لا يمنح صلاحية للأخرى.

## 3) نموذج MVP المستهدف

المسار التجاري والتعليمي المعتمد تصميميًا:

`Offer/Plan → Contract/Order → Entitlement → Enrollment → Learning → Completion → Certificate`

ويُمنع اختصار المسار إلى Enrollment مباشر عند بدء التشغيل التجاري.

### Entitlement states

- `PENDING`
- `ACTIVE`
- `SUSPENDED`
- `EXPIRED`
- `REVOKED`

فقط `ACTIVE` يسمح بالتسجيل/الدخول إلى محتوى البرنامج، مع بقاء قواعد الإكمال والشهادة مستقلة.

### Contract modes

- اشتراك فردي للمعلم.
- عقد مؤسسي بمقاعد قابلة للتخصيص.
- لا تُثبت أسعار أو مدد أو نسب خصم في هذه المرحلة؛ تبقى قرارًا تجاريًا منفصلًا.

## 4) Scoped RBAC المطلوب قبل التنفيذ الإنتاجي

الصلاحية يجب أن تُقيّم على أربعة عناصر:

`actor + capability + scope_type + scope_id`

Scopes المستهدفة:

- `ACADEMY_GLOBAL`
- `PROGRAM`
- `ORGANIZATION`
- `COHORT`

أمثلة قبول:

- مدير كتالوج عام يمكنه إدارة البرامج فقط وفق Capability صريحة.
- مشرف مؤسسة لا يرى بيانات مؤسسة أخرى.
- مدرب/مراجع برنامج لا يحصل على صلاحيات إدارة الاشتراكات تلقائيًا.
- أي Student role لا يتحول إلى Academy role.

## 5) مصفوفة التتبع للقبول

| المسار | الحالة المطلوبة | نتيجة الرفض المطلوبة |
|---|---|---|
| Teacher profile مكتمل + Entitlement فعال | دخول الأكاديمية والبرنامج المسموح | — |
| Teacher profile ناقص | إكمال ملف المعلم | لا Enrollment |
| Entitlement منتهي | عرض سبب الانتهاء وخيارات التجديد | منع المحتوى المحمي |
| مقعد مؤسسي مسحوب | تعليق الوصول | لا حذف لسجل التعلم |
| Student-only user | يبقى في مساحة الطالب | منع Academy capabilities |
| Dual persona | اختيار مساحة واضحة | لا مزج بيانات أو أدوار |
| Certificate eligible | إصدار شهادة برقم تحقق | — |
| Certificate revoked | صفحة تحقق تعرض الإلغاء | لا تعرض بيانات شخصية زائدة |
| Scoped admin خارج نطاقه | — | 403/رفض وظيفي واضح |

## 6) الشهادات

إصدار الشهادة يتطلب جميعًا:

- Enrollment صالح ومكتمل.
- استيفاء متطلبات البرنامج والتقييم.
- عدم وجود Suspension/Revocation يمنع الإصدار.
- Version ثابت للبرنامج عند الإكمال.

التحقق العام من الشهادة يعرض الحد الأدنى فقط:

- رقم الشهادة.
- اسم البرنامج.
- حالة الشهادة: valid/revoked.
- تاريخ الإصدار.
- اسم حامل الشهادة وفق سياسة الخصوصية المعتمدة لاحقًا.

لا يعرض البريد أو الهاتف أو بيانات Student profile.

## 7) معايير إغلاق كل بوابة

### QB_GATE

`PASS` فقط عند وجود قرار Cutover رسمي، Runtime غير LEGACY افتراضيًا، خطة Rollback، ونجاح regression المعتمد.

### IMPORT_GATE

`PASS` فقط بعد إخراج PR #96 من HOLD/Draft أو استبداله بعقد أحدث معتمد يغلق CF10/CF11 وPG17/E2E/RTL دون تسريب إجابات.

### ACADEMY_DOMAIN_GATE

`PASS` فقط بعد اعتماد Scoped RBAC وEntitlement/Contract lifecycle وإلغاء الاعتماد التجاري على `self_enroll` المباشر.

### SECURITY_GATE

`PASS` فقط عندما لا تبقى قدرة حذف عميق/تعطيل immutable protections كـ Release-governance blocker، مع عقد صلاحيات واختبارات سلبية موثقة.
