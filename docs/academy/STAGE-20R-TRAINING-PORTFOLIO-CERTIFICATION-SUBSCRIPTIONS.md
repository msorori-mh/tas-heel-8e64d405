## 1) قرار البوابة

بوابة البرمجة الكاملة لـ«أكاديمية معلم الثانوية» تبقى **مغلقة**.

هذه المرحلة لا تضيف Runtime جديدًا، ولا schema، ولا RPC، ولا Migration، ولا Deploy، ولا Payment integration، ولا Question Bank cutover. الغرض هو إغلاق تصميم الحزمة التدريبية وتجربة الاشتراك والشهادة قبل أي تنفيذ لاحق.

## 2) مبدأ الفصل بين الطالب والمعلم

الفصل التالي إلزامي وغير قابل للتنازل:

- واجهة المعلم مستقلة وظيفيًا عن واجهة الطالب.
- `STUDENT_PERSONA` لا تمنح أي Academy capability.
- اشتراك الطالب لا يمنح أي Teacher entitlement.
- شهادة الطالب لا تظهر داخل ملف المعلم المهني، والعكس صحيح.
- يمكن لنفس حساب المصادقة امتلاك شخصيتي طالب ومعلم، لكن كل شخصية لها مسار تنقل، بيانات عرض، صلاحيات، اشتراكات، تعلم وشهادات مستقلة.
- أي مشاركة مستقبلية للبنية التقنية لا يجوز أن تتحول إلى مشاركة صلاحيات أو اشتراكات ضمنية.

## 3) محفظة البرامج المقترحة للـMVP

### A. المسار التأسيسي المشترك للمعلمين

برنامج تأسيسي قصير يسبق البرامج التخصصية أو يعمل كمتطلب مشترك، ويغطي:

1. استخدام أكاديمية تمكين وإدارة الملف المهني.
2. تخطيط الحصة وربطها بمخرجات التعلم.
3. التقويم التشخيصي والتكويني والختامي.
4. التعامل مع الفروق الفردية ومعالجة التعثر.
5. الاستخدام المسؤول للأدوات الرقمية والذكاء الاصطناعي في التعليم.
6. مبادئ النزاهة الأكاديمية وحقوق المحتوى.

لا تُثبت مدة أو سعر في هذه المرحلة.

### B. المسارات التخصصية حسب المادة

ينشأ Program مستقل لكل مادة ثانوية مدعومة. البنية المرجعية لكل مسار:

1. **خريطة المنهج**: الوحدات، الدروس، الترابطات والمخرجات.
2. **المفاهيم الصعبة**: أكثر نقاط التعلم التي تحتاج شرحًا عميقًا.
3. **استراتيجيات التدريس**: أمثلة صفية ونماذج شرح.
4. **بناء السؤال والتقويم**: صياغة السؤال، المشتتات، مستويات الصعوبة، والتعليل.
5. **تحليل الاختبارات الوزارية**: الأنماط، الأخطاء المتكررة، واستراتيجيات المراجعة.
6. **العلاج والإثراء**: مسارات للطالب المتعثر والمتقدم.
7. **التطبيق العملي**: تجربة/محاكاة/نشاط تفاعلي عندما تكون طبيعة المادة مناسبة.
8. **التقييم الختامي**: Assessment مرتبط بإصدار البرنامج.
9. **مهمة ختامية**: درس أو خطة تدريس أو نموذج تقويم حسب طبيعة المادة.

### C. برامج قصيرة Micro-programs

بعد استقرار الـMVP يمكن تقديم برامج قصيرة مستقلة، مثل:

- تصميم اختبار جيد.
- بناء بنك أسئلة مصغر.
- إدارة الصف والتحفيز.
- التعليم العلاجي.
- توظيف المحاكاة والتجارب الرقمية.
- إعداد مراجعة نهائية للثانوية العامة.

هذه البرامج **خارج نطاق التنفيذ الأول** ولا تعتمد كمتطلبات إلزامية في الـMVP.

## 4) نموذج الإصدار Program Version

كل برنامج يجب أن يعمل بإصدارات ثابتة:

```text
Program
  └─ Program Version
      ├─ modules
      ├─ lessons
      ├─ required activities
      ├─ assessment policy snapshot
      ├─ completion policy snapshot
      └─ certificate policy snapshot
```

القواعد:

- المتعلم الذي بدأ Version لا يُنقل تلقائيًا إلى Version أحدث.
- تعديل البرنامج المنشور ينتج Version جديدًا.
- الشهادة تشير إلى Program Version محدد.
- نسب النجاح ومتطلبات الإكمال لا تتغير بأثر رجعي.

## 5) تجربة المعلم من البداية إلى الشهادة

### الحالة 1 — Teacher persona غير مكتملة

يرى المعلم استكمال الملف المهني فقط، ولا يرى أزرارًا توحي بوجود اشتراك نشط.

### الحالة 2 — لا يوجد Entitlement

يرى الكتالوج والمعلومات العامة المسموح بها، مع حالة واضحة:

`غير مشترك / تحتاج اشتراكًا أو مقعدًا مؤسسيًا`.

### الحالة 3 — Entitlement نشط

يمكنه الالتحاق بالبرنامج الذي يقع داخل Scope الاستحقاق فقط.

### الحالة 4 — Enrollment نشط

تظهر لوحة التعلم: التقدم، الوحدات، الأنشطة المطلوبة، التقييمات، والمتطلبات المتبقية.

### الحالة 5 — متطلبات الإكمال غير مستوفاة

لا يظهر زر إصدار شهادة. تعرض الواجهة المتطلبات المتبقية بوضوح.

### الحالة 6 — مكتمل ومستحق

تُصدر شهادة مرتبطة بالـEnrollment والـProgram Version والسياسة المجمدة.

## 6) الاشتراكات والعقود — التصميم التجاري دون تسعير

### Individual Teacher

```text
Plan -> Contract -> Entitlement -> Enrollment
```

### Organization Seats

```text
Plan -> Organization Contract -> Seat Allocation -> Teacher Entitlement -> Enrollment
```

قواعد إلزامية:

- الدفع أو العقد لا يساوي Enrollment.
- المقعد لا يمنح وصولًا حتى يُخصص لمعلم محدد.
- نقل المقعد لا ينقل تقدم أو شهادة المعلم السابق.
- انتهاء العقد لا يمحو تاريخ التعلم أو الشهادات الصادرة.
- سياسة grace period، refund، seat transfer، الأسعار والمدة تبقى Owner Decisions غير منفذة حتى اعتمادها.

## 7) الشهادات

### نوع الشهادة الافتراضي الآمن

حتى وجود اعتماد رسمي موثق، تسمى الشهادة:

**شهادة إتمام برنامج تدريبي**

ولا تستخدم عبارات مثل `شهادة معتمدة` أو `اعتماد مهني` إلا بمرجع قانوني/مؤسسي معتمد.

### شروط الإصدار

- Teacher persona صالح وفق السياسة.
- Enrollment مكتمل.
- كل المتطلبات الإلزامية مستوفاة.
- Assessment threshold مستوفى إن كان مطلوبًا.
- لا Certificate hold نشط.
- الإصدار مرتبط ببرنامج Version محدد.

### التحقق العام

يعرض صفحة التحقق العامة الحد الأدنى فقط:

- اسم المعلم.
- اسم البرنامج.
- إصدار البرنامج.
- تاريخ الإصدار.
- حالة الشهادة `VALID / REVOKED`.

ولا تعرض تفاصيل الدفع أو العقد أو بيانات مهنية حساسة.

## 8) الأدوار التشغيلية المقترحة

### Teacher Learner

- يتعلم ويراجع تقدمه وشهاداته فقط.
- لا يدير محتوى أو مشتركين أو شهادات الآخرين.

### Program Manager

- يدير برامج ضمن Scope محدد.
- لا يمنح نفسه Entitlement ولا يتجاوز Scope.

### Content Manager

- يدير المحتوى ضمن Scope محدد.
- لا يدير العقود أو المدفوعات أو إصدار الشهادات يدويًا.

### Assessment Manager

- يدير التقييمات ضمن Scope محدد.
- لا يصل إلى العقود أو الاشتراكات.

### Organization Manager

- يدير مقاعد مؤسسته فقط.
- لا يصل إلى مؤسسات أخرى أو الكتالوج العالمي.

### Auditor

- قراءة وتدقيق فقط.
- صفر writes.

### Academy Super Admin

- إدارة شاملة للأكاديمية فقط وفق ضوابط أمنية معززة.
- لا يرث صلاحيات من Student Admin role تلقائيًا.

## 9) معايير قبول تجربة الاستخدام

- التنقل في الأكاديمية يحمل هوية بصرية ومسارات مستقلة عن تطبيق الطالب.
- لا تظهر عناصر طالب داخل Teacher workspace.
- لا تعرض الواجهة زرًا غير صالح بسبب نقص entitlement أو scope؛ تعرض حالة مفهومة بدلًا من ذلك.
- جميع حالات الرفض تترجم إلى رسائل UX دون كشف تفاصيل authorization الداخلية.
- الهاتف هو المرجع الأول لتصميم الـMVP.
- RTL كامل، مع وضوح progress ومتطلبات الإكمال والشهادة.
- الوصول إلى الشهادة والتحقق منها لا يتطلب العودة إلى تطبيق الطالب.

## 10) خطة التنفيذ بعد فتح البوابات

### المرحلة A — Pure non-production

يسمح بها فقط بعد فتح البوابة المناسبة:

- Mock fixtures.
- Pure validators/reducers.
- Component tests.
- A11y/RTL tests.
- بدون Network أو Supabase أو Payment أو QB runtime.

### المرحلة B — Isolated staging

بعد اعتماد العقود والصلاحيات:

- Scoped RBAC.
- Contract/Entitlement lifecycle.
- Enrollment enforcement.
- Certificate lifecycle.
- Staging-only integration tests.

### المرحلة C — Production readiness

لا تبدأ إلا بعد:

- Question Bank formal gate PASS.
- Import Contract formal gate PASS.
- Scoped RBAC + subscriptions/entitlements PASS.
- Security blocker closure PASS.
- rollback/evidence/release checklist مكتملة.

## 11) قرارات تبقى خارج التنفيذ

لا يتم افتراض القيم التالية:

- سعر الاشتراك.
- مدة الاشتراك.
- الخصومات.
- سياسة الاسترداد.
- فترة السماح.
- سياسة نقل المقاعد.
- اسم الجهة المصدرة على الشهادة.
- أي ادعاء اعتماد رسمي.
- أثر Revocation للعقد على شهادة صدرت سابقًا إلا بعد اعتماد سياسة واضحة.

## 12) Exit Criteria لـStage 20R

تعتبر هذه المرحلة مكتملة تصميميًا عندما تكون البنود التالية مثبتة ومراجعة:

1. محفظة الـMVP وحدود البرامج القصيرة.
2. بنية Program Version.
3. رحلة المعلم من persona إلى certificate.
4. نموذج Individual + Organization subscriptions.
5. حدود الأدوار.
6. سياسة شهادة الإتمام الآمنة.
7. UX acceptance states.
8. قائمة Owner Decisions التي لا يجوز للكود تخمينها.
