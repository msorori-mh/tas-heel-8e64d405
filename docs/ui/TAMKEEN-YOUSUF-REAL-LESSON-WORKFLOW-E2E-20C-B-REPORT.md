## 2. قواعد الحالة (Fail-Closed)

- لا صف دورة حياة ⇒ سلوك 20B القديم (لا إخفاء صامت للمحتوى القائم).
- `READY` ⇒ يُعرض للطالب.
- `DRAFT` / `REVIEW` بلا نسخة معتمدة سابقة ⇒ لا يُعرض للطالب إطلاقاً.
- `DRAFT` / `REVIEW` مع نسخة معتمدة مجمّدة ⇒ الأدمن يرى «مسودة»، والطالب يستمر في رؤية النسخة المعتمدة (لا انقطاع للمحتوى).
- الطالب لا يقرأ أصلاً إلا صفوف `READY` (RLS)، والبوابة في الواجهة تُطبَّق فقط على الدروس المُدارة (التي تملك صفوف دورة حياة).

## 3. الإثبات E2E على درس القرآن

| الخطوة | النتيجة |
| --- | --- |
| الحالة الابتدائية | المسار التحريري: معتمد — الطالب يرى قسم «شرح إضافي» |
| ضغط «إنشاء نسخة تعديل (مسودة)» | الحالة صارت مسودة، ملاحظة تشغيلية ظهرت في مساحة العمل |
| صفحة الطالب أثناء المسودة | قسم «شرح إضافي» **اختفى** (باقي الأقسام كما هي) |
| `?preview=1` بحساب فريق المحتوى | شارة «وضع المعاينة» ظهرت، والقسم **مرئي** في المعاينة فقط |
| «إرسال للمراجعة» ثم «اعتماد ونشر للطالب» | الحالة رجعت إلى معتمد (`reviewed_at` مسجّل) |
| صفحة الطالب بعد الاعتماد | قسم «شرح إضافي» **عاد للظهور** |

الحالة النهائية في الإنتاج: 5 قدرات للدرس كلها `READY` (كما كانت قبل الاختبار) — لا أثر متبقٍ.
