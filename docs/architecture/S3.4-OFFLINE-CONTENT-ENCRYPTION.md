# S3.4 — Native content encryption and installed-APK compatibility

Baseline: main `e2613cbe68971cf39349771d11bfc7f89f1859cf`, PR #223
`10b2427c37a5f3c23df286d5a456f8fc621ae60c`. Environment: local and isolated CI.

Scope: native pack artifacts, their legacy migration, the native lesson/PDF
readers and shared code compatibility with the existing remote-shell APK.
No production data, migrations, Auth configuration or release signing changed.

## Storage and migration

- New Android binaries use a distinct Android Keystore AES-GCM key and `TKA2`
  authenticated envelopes under `tamkeen/offline-artifacts-v2`. Owner, digest,
  path and size are authenticated as additional data. A copied envelope cannot
  become another owner's artifact or another path's artifact.
- The bridge resolves incoming artifact identity against the active owner's
  registered manifests. PDF display additionally requires READY and the
  verified-artifact list. Neither bridge accepts an arbitrary filesystem path.
- AtomicFile plus a shared native lock protects writes. SHA-256, size and
  encrypted read-back must succeed before deleting matching legacy plaintext.
  A failed encrypted read never falls back to plaintext. A fresh, verified
  download may repair damaged ciphertext.
- Legacy owner files migrate on access. Older shared PDF bytes are retained
  until every referencing account/revision has a verified encrypted copy.
  Newly downloaded packs no longer create the historical plaintext PDF mirror.
  Unaccessed legacy files are not claimed to be encrypted by this migration.
- PDFium receives a seekable descriptor whose temporary filename is unlinked
  **before** any plaintext is written. Closing the renderer/process releases
  the descriptor. No named decrypted PDF is persisted or returned to JavaScript.
  The descriptor contains plaintext while the document is being displayed.
- Browser IndexedDB remains origin-private and subject to browser eviction;
  this stage does not claim Keystore encryption for the web client.

## Compatibility

Plugin capability is checked before selecting the native state/content
adapter. Existing APKs without the new plugins retain their historical private
file adapter. New binaries never downgrade to plaintext because of a Keystore,
database, authentication or disk error. Invalid legacy state/storage errors
must not silently become empty state. The legacy adapter retains the older
single-WebView serialization model; native CAS requires the binary upgrade.

Downgrading a migrated binary is not a supported recovery operation: older
binaries cannot read ciphertext. Preserve the installation/key and pending
activity, repair forward, and verify replay before any intentional reset.
