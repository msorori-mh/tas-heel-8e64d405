# S3.5 — Student profile completion in the bundled client

Baseline: PR #223 `05f3ccb6075203369bea9fa3158ebaf0ae29e9c9`.
S3.4 passed all four workflows, including 14 Android instrumentation tests and
8 offline Chromium checks. This stage closes the missing-profile dead end.

The local client now provides an Arabic profile form for name, grade,
governorate, curriculum track and optional school. Choices come from the same
existing tables and governorate mapping as the website. Incomplete profiles
open the form from the subject catalog; successful, verified saves reload the
appropriate subjects. Network loss retains the open form and disables submit.

Writes keep the existing RLS and triggers, pin the account's access token,
allow-list profile fields, check active owner before/after the request, and
verify the returned row. No roles, credentials or unrelated profile fields
are accepted from the form. A rejected request is not reported as saved.
Leaving the form cancels its in-flight operations. No production test writes
or schema migrations are used.

The existing connected application remains available through a clearly
labeled system-browser entry for official exams/results, settings, teacher
and admin services. URLs contain no tokens. These services require Internet
and may require browser sign-in; they are not bundled/offline parity. External
PhET simulations also still require Internet.

Evidence: the expanded browser journey starts with an incomplete profile,
checks denied save/retry and network loss without clearing the form, then
saves and uses the actual subject downloader before the existing offline
reload/lesson/answer/grading/logout journey. Four unit tests exercise field
and account boundaries, cancellation and response verification. Exact commit
CI results are recorded in PR #223.

Release remains HOLD for the signed physical-device upgrade and lifecycle
acceptance documented in S3.3. No merge, deployment or signed release was
performed by this stage.
