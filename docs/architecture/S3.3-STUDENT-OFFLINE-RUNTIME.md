# S3.3 — Bundled student learning runtime

Release decision: **HOLD pending runtime CI and physical-device acceptance**.

Baseline: main `e2613cbe68971cf39349771d11bfc7f89f1859cf`.
This branch isolates the local-shell and encrypted-state work from the unrelated
infrastructure transfer in PR #214. It includes the offline changes from
#215/#216 and preserves the existing production backend configuration.

## Implemented

- A standalone Arabic student client in `apps/student-mobile` builds to
  `dist-student-mobile`, which is the Capacitor release entry.
- The first screen reads the active owner and installed packs locally before
  waiting for Auth or the network. Google login uses the existing PKCE native
  callback. Sign-out hides local content while retaining pending answers.
- Students can list their grade/track subjects, download/update packs, read
  verified lesson text and PDFs, answer official-book questions, and grade
  self-test questions from the installed answer layer.
- Browser shell assets have a versioned service-worker cache. API responses,
  credentials and external resources are excluded from that cache.
- State writes use optimistic revision checks and a common native lock, with
  bounded retries. Corrupt legacy state fails closed instead of becoming an
  empty successful migration.
- Artifacts are addressed by owner and content hash. Native reads no longer
  depend on WebView IndexedDB metadata. The previously installed revision
  remains readable while an update is incomplete.
- Foreground synchronization drains successive batches, retries without a
  new connectivity event, fences late acknowledgements, captures the matching
  account token for each request, and stops on abort or account mismatch.
- Download and response size verification remain mandatory before a pack
  becomes readable. Student answers are persisted before revealing feedback.

  Tests use isolated TEST_ONLY files/databases, never application data.

Before merging or shipping, verify the actual signed upgrade on a physical
Android device: login/download, force-stop, airplane-mode cold start, reboot,
answers saved for multiple days, reconnect without duplicates, account switch,
low storage, interrupted update, and recovery after the WebView cache is cleared.
The existing Google callback allow-list and live backend access must be checked
with a test account. Unit tests or the emulator do not substitute for this gate.

## Scope limits

- PhET wrappers with remote iframes still require the Internet; the client
  labels them and enables only the PhET origin after an explicit student action.
  An external wrapper must not be described as an offline simulation.
- This client supplies the student lesson-learning journey. Full parity with
  the remote application's official-exam, onboarding, teacher and admin flows
  is not established by this stage and must be reviewed before changing the
  distributed application entry.
- Native state is encrypted using Android Keystore. Downloaded content files
  remain in app-private storage; content encryption is not completed here.
- Web storage can be evicted by the browser. The client requests persistent
  storage when a student downloads; the platform may decline that request.

No production migration, Auth setting, DNS change, merge or deployment is part
of this unapproved release result. Do not downgrade an installation with pending
activity to a state format that cannot read it; sync and verify first.
