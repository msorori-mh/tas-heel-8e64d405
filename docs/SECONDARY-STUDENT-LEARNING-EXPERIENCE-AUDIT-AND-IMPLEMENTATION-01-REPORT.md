# SECONDARY-STUDENT-LEARNING-EXPERIENCE-AUDIT-AND-IMPLEMENTATION-01

## النطاق والنتيجة

راجعت مسار الطالب من الصفحة الرئيسية إلى المادة والوحدة والدرس، مع التركيز على الهاتف، حالات الفراغ والفشل، وضوح الوصول المجاني، والتنقل. النتيجة الحالية: **PASS ضمن نطاق واجهة الطالب** بعد نجاح فحوص المشروع، ولا توجد ملاحظات CRITICAL أو HIGH أو MEDIUM مفتوحة ضمن الملفات المملوكة لهذه المهمة.

## الحالة حسب النظام

| النظام             | الحالة       | الملاحظة                                                                                            |
| ------------------ | ------------ | --------------------------------------------------------------------------------------------------- |
| الصفحة الرئيسية    | مكتمل        | اختيار الفصل، ملخص التقدم، المتابعة، والمواد ظاهرة بمسارات واضحة.                                   |
| المواد والوحدات    | مكتمل جزئياً | واجهة الفهرس موجودة وتراعي الصف/المسار في الواجهة؛ صحة RLS/RPC تقع ضمن مهمة الوصول الأمني المستقلة. |
| الدروس والموارد    | مكتمل جزئياً | المحتوى والموارد وحالات عدم التوفر موجودة؛ التحقق الخلفي والصلاحيات خارج نطاق هذه المهمة.           |
| التقدم             | مكتمل جزئياً | الملخص والمتابعة موجودان؛ دقة البيانات تعتمد على بيانات المصدر واختبارات التكامل.                   |
| التنقل والبحث      | مكتمل جزئياً | التنقل الأساسي واضح ومتوافق مع الهاتف؛ لا توجد حالياً واجهة بحث عامة للمواد والدروس.                |
| تجربة الهاتف       | مكتمل        | عولج ازدحام شريط التنقل عند العرض الضيق مع إبقاء أسماء قابلة للوصول للأيقونات.                      |
| حالات الفراغ/الفشل | مكتمل        | أضيفت إعادة محاولة عند فشل المواد ومسار واضح لاختيار فصل آخر عند الفراغ.                            |
| وضوح المجانية      | مكتمل        | الصفحة الرئيسية وفهرس المادة يوضحان أن المحتوى مجاني للطلاب المسجلين، دون CTA دفع.                  |

## التعديلات

- جعل شريط الطالب آمناً للشاشات الضيقة وتحسين حالات التركيز والتسميات المساعدة.
- إضافة استعادة مباشرة عند فشل تحميل المواد، ومنع اجتماع رسالة الخطأ مع حالة الفراغ.
- تحويل فراغ الفصل إلى حالة قابلة للتصرف عبر اختيار فصل آخر.
- إضافة دلالات تحميل مناسبة لقسم متابعة الدروس.

## Smoke المقترح/المنفذ

1. فتح `/app` كطالب مسجل والتحقق من ظهور رسالة الوصول المجاني.
2. اختيار الفصل ثم فتح مادة من القائمة.
3. فتح درس من وحدة والعودة عبر مسار التنقل.
4. التحقق من حالة فصل بلا مواد وإمكانية الرجوع لاختيار فصل آخر.
5. محاكاة فشل طلب المواد والتحقق من ظهور رسالة آمنة وزر إعادة المحاولة.
6. فحص شريط التنقل عند عرض هاتف ضيق والتحقق من بقاء الأزرار قابلة للوصول بلوحة المفاتيح وقارئ الشاشة.

## نتائج التحقق

- `eslint` scoped للملفات الثلاثة المعدلة: **PASS**.
- `tsc --noEmit`: **PASS**.
- Vite client + SSR production build: **PASS** (مع تحذير حجم chunk قائم وغير حاجب).
- `git diff --check`: **PASS**.
- لا يوجد test runner معرف في `package.json`، لذلك لم تُضف اختبارات آلية تتطلب تغيير إعدادات الحزم.
- ملاحظة baseline: `npm ci` غير قابل للتنفيذ لأن `package-lock.json` لا يطابق إصدارات `package.json`؛ استُخدمت اعتماديات workspace المتاحة للتحقق دون تعديل أي manifest أو lockfile.

## فجوات خارج النطاق

- **P1:** بحث عام للمواد والدروس غير منفذ؛ يحتاج قراراً حول مصدر البحث وترتيب النتائج قبل التنفيذ.
- **P1:** مزامنة `package-lock.json` مع `package.json` في مهمة صيانة مستقلة كي يعود `npm ci` قابلاً للتكرار.
- اختبارات الصلاحيات الخلفية وRLS/RPC، ومنع وصول صف/منهج خاطئ، مملوكة لمهمة الوصول المجاني والأمن.
- دقة تقدم الطالب وتحليل الاختبارات مملوكة لمهمة الاختبارات والأداء.

## ضمانات السلامة

- لم تُعدّل migrations أو RPCs أو auth/route guards أو منطق الاختبارات.
- لم تُعدّل صفحات الدفع أو المحفظة أو الاشتراكات ولم تُحذف بنيتها.
- لم يحدث Deploy أو Publish أو كتابة إنتاجية أو تعديل لبيانات طلاب.
