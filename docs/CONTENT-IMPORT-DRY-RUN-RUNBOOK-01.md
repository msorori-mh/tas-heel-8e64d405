# CONTENT-IMPORT-DRY-RUN-RUNBOOK-01 — دليل تشغيل dry-run للمحتوى

> **الغرض:** فحص ملفات المحتوى التعليمي (قوالب 01–09) **قبل** أي استيراد فعلي.
> dry-run **قراءة فقط**: يحلّل الملف ويتحقق منه ولا يكتب أي بيانات في قاعدة البيانات.
> **المسؤول عن التشغيل:** يوسف (فريق المحتوى) بحساب content_manager أو admin.
> **المكان:** صفحة `/admin/import` في التطبيق.

---

## 1. ترتيب إدخال الملفات (إلزامي)

```
01 subjects        المواد الدراسية
  → 02 units       الوحدات
    → 03 lessons   الدروس (lesson_code يُستخدم في كل ما بعده)
      → 04 book_contents   محتوى الكتاب
      → 05 explanations    الشروحات
        → 06 resources     الموارد والروابط
      → 09 questions       بنك الأسئلة (أولاً!)
        → 07 assessments   تقييمات الدروس
        → 08 assessment_questions   ربط الأسئلة بالتقييمات
```

- لا تبدأ 04–08 قبل اعتماد 03 (الأكواد تُربط بـ `lesson_code`).
- 09 قبل 08 دائماً (الربط يحتاج `question_code`).

## 2. كيفية تشغيل dry-run لكل قالب

1. افتح `/admin/import` وسجّل الدخول بحساب طاقم المحتوى.
2. اختر نوع القالب (01–09) من الواجهة.
3. ارفع ملف `.xlsx` المعبّأ (الحد الأقصى 5MB و1000 صف بيانات).
4. شغّل الفحص — تظهر النتيجة فوراً بحالة: **pass / warn / fail** مع:
   - عدد الصفوف الكلي والصالح.
   - قائمة الأخطاء (مع رقم الصف والعمود).
   - قائمة التحذيرات.
   - معاينة لأول 10 صفوف والأعمدة المكتشفة.
5. صدّر/صوّر النتيجة وأرفقها مع الملف عند التسليم للمراجعة.

كرر لكل قالب بالترتيب في القسم 1. **لا ينتقل فريق المحتوى للقالب التالي قبل أن يكون الحالي pass أو warn مبرر.**

## 3. قراءة النتيجة

### الأخطاء المانعة (status = fail — يجب إصلاحها قبل المتابعة)

| الكود | المعنى | الإصلاح |
|---|---|---|
| `MISSING_COLUMN` | عمود مطلوب غير موجود في الملف | أضف العمود بالتسمية الصحيحة تماماً |
| `EMPTY_FILE` | لا صفوف بيانات | عبّئ الملف |
| `ROW_LIMIT` | أكثر من 1000 صف | قسّم الملف |
| `MISSING_VALUE` | حقل مطلوب فارغ في صف | عبّئ الحقل |
| `DUPLICATE_KEY` | تكرار كود (`subject_code`/`unit_code`/`lesson_code`/`assessment_code`/`question_code` أو زوج assessment+question) | وحّد الأكواد — كل كود فريد |
| `INVALID_RESOURCE_TYPE` | `resource_type` خارج القيم المسموحة | video \| mindmap \| experiment \| pdf \| link فقط |
| `MISSING_OPTION` | `option_1`/`option_2` فارغ في سؤال | عبّئ الخيارين الإلزاميين |
| `MISSING_CORRECT_INDEX` / `INVALID_CORRECT_INDEX` | `correct_index` مفقود أو ليس رقماً صحيحاً 1–6 | صحّح القيمة |
| `CORRECT_INDEX_NO_OPTION` | `correct_index` يشير لخيار فارغ | عبّئ الخيار أو صحّح الرقم |

### التحذيرات غير المانعة (status = warn — راجعها وبرّرها أو صحّحها)

| الكود | المعنى | الإجراء |
|---|---|---|
| `EXTRA_COLUMN` | عمود غير معروف في القالب | احذفه أو تأكد أنه ملاحظات تحريرية |
| `INFO` | ملاحظات تشغيلية (ربط الأكواد لاحقاً، أعمدة الإجابة للمحررين فقط) | اقرأها فقط |
| `NONSTANDARD_SEPARATOR` | فاصل غير موحد في اسم مادة (– — − ‐ ―) | حوّله إلى `" - "` (مسافة+شرطة+مسافة) |
| `NONSTANDARD_PARENT_SPELLING` | «الإسلامية - ...» | المعتمد: «التربية الإسلامية - ...» |
| `PARENT_SPELLING_MISMATCH` | هجاءان لنفس المادة الكبرى | وحّد الاسم الكبير حرفياً وإلا ظهرت كمادتين للطالب |

> التحذيرات لا تمنع dry-run، لكن **تحذيرات التسمية تكسر تجميع المواد في واجهة الطالب عملياً** — عاملها كأخطاء قبل الاستيراد.

## 4. التحقق من أسماء المواد المقسمة

1. الصيغة: `اسم المادة الكبرى - اسم القسم الفرعي` والفاصل `" - "` حرفياً.
2. القيم الثماني المعتمدة للصف الأول في `docs/SUBJECT-GROUPING-GRADE-10-YEMEN-CONTENT-GUIDE.md`.
3. في قالب 01: رتّب الصفوف بـ sort_order المعتمد (1–8) وتأكد أن كل أقسام العائلة الواحدة بنفس الهجاء حرفاً بحرف.
4. أي `NONSTANDARD_*` / `PARENT_SPELLING_MISMATCH` في نتيجة dry-run = صحّح الملف وأعد الفحص.

## 5. التحقق من سلسلة الربط grade → subject → unit → lesson → questions → exam_template

| الوصلة | كيف تتحقق |
|---|---|
| grade → subject | في 01: `grade_slug` موجود فعلاً (`grade-10`/`grade-11`/`grade-12`)، و`track_code` صحيح إن استُخدم |
| subject → unit | في 02: كل `subject_code` موجود في ملف 01 المعتمد |
| unit/subject → lesson | في 03: كل `subject_code` (و`unit_code` إن استُخدم) معرّف سابقاً |
| lesson → محتوى/موارد | في 04–06: كل `lesson_code` موجود في 03 |
| lesson/subject → questions | في 09: `lesson_code`/`subject_code` (إن وُجدا) معرّفان سابقاً؛ `correct_index` يشير لخيار معبّأ |
| questions → assessments | في 08: كل `question_code` في 09 وكل `assessment_code` في 07 |
| exam templates | نماذج الاختبارات تُدار من `/admin/exam-templates` وتُربط بأسئلة بنك 09 — تأكد أن كل نموذج نشط له أسئلة كافية |

> dry-run يتحقق داخل الملف الواحد؛ التحقق **بين** الملفات يدوي بمقابلة الأكواد (أو بجرد قاعدة البيانات بعد الاستيراد).

## 6. Checklist نهائية قبل أي import فعلي

- [ ] **لا وحدات QA** في بيانات الإنتاج (بانتظار تنظيف المالك — لا يبدأ import قبلها).
- [ ] أسماء المواد موحدة الهجاء (صفر تحذيرات تسمية).
- [ ] `subject_code` غير مكرر (صفر `DUPLICATE_KEY` في 01).
- [ ] `unit_code` غير مكرر داخل المادة (صفر تكرار في 02).
- [ ] `lesson_code` غير مكرر داخل الوحدة (صفر تكرار في 03).
- [ ] `question_code` غير مكرر (صفر تكرار في 09).
- [ ] كل `correct_index` صالح ويشير لخيار معبّأ.
- [ ] كل نماذج الاختبار المخطط تفعيلها مرتبطة بأسئلة من 09.
- [ ] كل القوالب 01–09 بحالة pass أو warn مبرر وموثق.
- [x] migration تقييد units مطبقة عبر Lovable — PRE-IMPORT-UNITS-RLS-HARDENING-APPLY-01 = PASS (main @ f5d714d).
- [ ] تفويض كتابي من المالك لبدء الاستيراد الفعلي.

## 7. بعد dry-run الناجح

1. سلّم الملفات + نتائج الفحص للمالك.
2. المالك يصرّح بالاستيراد الفعلي (خارج نطاق هذا الدليل ويحتاج تفويضاً صريحاً).
3. بعد الاستيراد: smoke طالب كامل (مادة ← وحدة ← درس ← تدريب ← اختبار ← نتيجة).
