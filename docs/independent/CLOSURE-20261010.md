## Read-only data and storage inventory

`scripts/independent/collect-inventory.mjs` pins a known project in the database connection, verifies TLS and runs a repeatable-read, read-only transaction with statement/lock timeouts. It does not change roles, policies, ownership, data, files or migration ledgers.

Provide `DATABASE_URL` privately in the executing process, not in chat or a command committed to Git. With a certificate authority supplied by the database provider, set `PGSSLROOTCERT` to the local certificate file. Never work around TLS failures by disabling certificate verification.

Run once per endpoint:

```sh
node scripts/independent/collect-inventory.mjs yjpirilbpqxtmnayruht target-inventory.json
node scripts/independent/collect-inventory.mjs zbdhxyuulyovihjgeqbn source-inventory.json
```

Change DATABASE_URL to the corresponding project before each invocation. Reports include exact table counts, hashes of columns/functions/policies, RLS flags, bucket settings, aggregate orphan ownership counts and the migration ledger when available. They omit user rows, emails, object paths, session tokens and function bodies. The output file is created exclusively to avoid overwriting previous evidence.

`READ_ONLY_INVENTORY_NOT_PARITY_PROOF` is intentional: equal counts and schema hashes do not prove equal rows or file bytes, and separate database snapshots are not simultaneous. Do not bulk replay migrations based on this report. A live schema drift review, keyed row comparison, deleted-row handling and a controlled write-freeze/cutover window are still required.
