# المرحلة 1: بيئة اختبار مستقلة لتطبيق تمكين

الهدف: نشر نسخة HTTPS على Supabase المستقل وبناء APK منفصل للاختبار.
خط الأساس: `96e57b3bd84dba6b87110da3e7f8989413e7c264` (1.1.4، رقم 9).
الفرع: `feat/independent-staging-20261009`.
لا يتضمن هذا المسار تحويل النطاق الإنتاجي أو ترحيل سجلات إضافية أو نشر Flutter.

## استضافة Render أو خادم Node.js مماثل

- المستودع: `msorori-mh/tas-heel-8e64d405`، الفرع أعلاه.
- Runtime: Node.js 22 أو أحدث.
- Build: `npm ci && npm run build:independent && node scripts/independent/verify-build.mjs`.
- Start: `npm run start:independent`.
- متغير `TAMKEEN_STAGING_ORIGIN`: عنوان HTTPS المستقل الفعلي دون مسار؛ لا تستخدم النطاق الإنتاجي.
- سر `SUPABASE_SERVICE_ROLE_KEY`: مفتاح الخادم للمشروع `yjpirilbpqxtmnayruht`، يُدخل في إعدادات أسرار الاستضافة فقط.
- المضيف `0.0.0.0` والمنفذ من `PORT`، والافتراضي `10000`.
- لا تضف السر إلى متغير يبدأ بـ`VITE_` أو إلى ملفات المستودع أو APK.
- المشروع ومفتاحه العام مثبتان في إعداد البناء؛ لا يُختار مشروع Lovable القديم عند غياب الإعداد.
- بدء الخادم يتحقق من تطابق عنوان البناء ومن قبول المفتاح في المشروع الهدف، وإلا يتوقف ويظهر HTTP status فقط.
- خطة الاستضافة وحسابها يُحددان عند ربط الحساب؛ لا يُفترض وجود اشتراك مدفوع أو يُنشأ تلقائيًا بهذا الكود.

## تسجيل الدخول

في Supabase المستقل، أضف Redirect URLs التالية مع استبدال `STAGING_ORIGIN` بالعنوان الفعلي:

- `STAGING_ORIGIN/auth/callback`
- `STAGING_ORIGIN/auth/mobile-callback`
- `STAGING_ORIGIN/academy/callback`
- `app.studentamkeen.tamkeen.staging://auth/callback`

اترك روابط الإنتاج كما هي. callback في Google Cloud يبقى callback الخاص بمشروع Supabase المستقل.

## APK منفصل

بعد نشر نفس commit والتحقق من تشغيله:

1. ضع عنوان HTTPS الفعلي في GitHub Actions repository variable باسم `TAMKEEN_STAGING_ORIGIN`.
2. أعد تشغيل مسار `Independent staging web and Android` لنفس commit بعد اكتمال نشره.
3. المسار يتحقق من `/independent-release.json` ورأس الاستجابة، ثم يبني APK.
4. اسم التطبيق `تمكين — اختبار مستقل` ومعرّفه `app.studentamkeen.tamkeen.staging`؛ لا يستبدل التطبيق الأصلي.
5. هذه نسخة اختبار debug فقط، ولا تُرفع إلى Google Play. توقيع نسخ debug قد يتغير بين تشغيلات CI؛ لا تفترض قابليتها للتحديث فوق نسخة اختبار قديمة.
6. تنزيلات المتصفح على الكمبيوتر لا تنتقل إلى الهاتف؛ نزّل المحتوى مرة داخل نسخة الاختبار.

لا يُنتج APK يشير إلى عنوان غير منشور أو إصدار خادم مختلف. في غياب متغير الاستضافة يبني CI دليل صلاحية خادم Node بعنوان `.invalid` فقط، ويتجاوز بناء APK عمدًا؛ هذا ليس نشرًا ولا نسخة قابلة لاختبار الهاتف.

## التحقق وحدود الإغلاق

- فحص الدخول بحساب الطالب ثم حساب الإدارة، وعدم منح صلاحية إدارية للطالب.
- تنزيل درس ثم فتح المكونات دون إنترنت، إغلاق التطبيق وإعادة فتحه، وعودة الاتصال.
- التحقق من رفض الجلسة الملغاة عند عودة الاتصال وعدم عرض محتوى مستخدم آخر.
- اكتمال نقل تغييرات البيانات الأخيرة ومراجعة حالات ملكية التخزين بوابة منفصلة قبل التحويل الإنتاجي.
- استعادة الاختبار: إيقاف خدمة الاستضافة التجريبية فقط. لم يُعدّل عنوان الإنتاج أو حزمة التطبيق الحالية.
