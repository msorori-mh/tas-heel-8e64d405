# دليل فريق المحتوى: رفع وتشغيل موارد HTML التفاعلية (إصدار 17 و 19 التصحيحي)

**المستند**: `CONTENT-ONBOARDING-HTML-TEAM-UPLOAD-RUNBOOK-AR-17`  
**الهدف**: توضيح الخطوات والضوابط العملية لفريق المحتوى لرفع واختبار واعتماد الموارد التفاعلية (الخرائط الذهنية والتجارب العملية) وفق عقود الأمان الخادمية وحالات التشغيل الفعلي.

---

## 1. شروط وقواعد إعداد حزمة HTML

عند إعداد حزمة موارد HTML، يجب الالتزام الصارم بالشروط الأمنية والفنية التالية:

1. **الهيكل الداخلي للحزمة (ZIP)**:
   - يجب أن تحتوي الحزمة على ملف `index.html` رئيسي.
   - يجب إدراج ملف `manifest.json` يحدد كود المورد والإصدار.
   - جميع المراجع لملفات CSS والصور وJavaScript يجب أن تكون نسبية (Relative Paths).
2. **منع الإحداثيات الخارجية والروابط المباشرة (Fail-Closed Security)**:
   - يمنع استخدام نصوص برمجية من خوادم خارجية (`<script src="https://...">`).
   - يمنع استخدام `eval()` أو `sendBeacon` أو WebRTC.
3. **حظر تسريب الإجابات أو الشروحات ومعلومات الطلاب (No Answer Key / PII Leakage)**:
   - يُمنع تماماً تضمين حقول الإجابات الصحيحة أو الشروح المعلمة مثل `data-answer` أو `correct-answer` أو `answer-key` أو `explanation` أو بيانات الطلاب الشخصية PII داخل ملفات HTML أو JS أو JSON بالحزمة.
   - الفحص الأمني الخادمي (Server-side Package Validator) يرفض الحزمة تلقائياً وبشكل قاطع عند اكتشاف أي من هذه المخالفات.

## 2. خطوات رفع واستيراد المحتوى عبر الواجهة

1. **الخطوة الأولى: إعداد البيانات في ملف Excel**:
   - استخدام قالب استيراد الموارد التفاعلية 06 (`interactive_lesson_resources_template.xlsx`).
   - تحديد كود الدرس (`lesson_code`) وكود المورد (`resource_code`).
2. **الخطوة الثانية: تشغيل الفحص والتأكد من تفعيل Feature Flags**:
   - الانتقال إلى واجهة استيراد المحتوى `/admin/import`.
   - التأكد من حالة Feature Flags الخادمية (`html_content_backend` و `html_content_upload`).
   - عند إيقاف الفلاغ، تعمل الواجهة في وضع المحاكاة الصريحة (Simulator Mode).
3. **الخطوة الثالثة: إرسال المورد للمراجعة (Submit for Review)**:
   - بعد اجتياز الفحص الخادمي بنجاح 100% وتسجيل نتيجته الموثوقة في القاعدة (`content_package_validations`)، يتم إرسال المسودة للمراجعة الإدارية (`submit_resource_for_review`).
4. **الخطوة الرابعة: الاعتماد والنشر (Approve & Publish)**:
   - يقوم مدير النظام (Admin) بفتح واجهة المراجعة `/admin/content-review`.
   - مراجعة المحتوى والتأكد من الفحوصات الأمنية.
   - اتخاذ قرار **الاعتماد (Approve)** الذي يضبط النسخة كغير قابلة للتعديل (`immutable_at`) ثم **النشر (Publish)** الذي ينقل المحتوى إلى مسار التخزين المنشور الموثق بقفل `lock_version`.
   - فور النشر، يصبح المورد متاحاً للطالب داخل صفحة الدرس المحدد حصراً عبر `fetch_published_lesson_resources`.

---

## 3. التدابير الأمنية وضمان الخصوصية

- **حظر بيئة Capacitor على الهواتف**: تشغيل HTML يبقى معطلاً افتراضياً في Runtime المحمول لحماية التطبيق (Fail-closed).
- **العزل التام (Iframe Sandbox)**: يتم تشغيل المحتوى داخل إطار معزول بتقييد strict CSP.
- **خصخصة التخزين والروابط الموقعة**: حزم HTML تُحفظ داخل Storage Buckets خاصة (`private`) ولا يمكن الوصول إليها إلا عبر Signed URLs قصيرة الأجل وللطلاب المصرح لهم بالدرس فقط.
