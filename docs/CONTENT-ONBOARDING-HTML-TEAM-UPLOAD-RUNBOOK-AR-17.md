# دليل فريق المحتوى: رفع وتشغيل موارد HTML التفاعلية (إصدار 17)

**المستند**: `CONTENT-ONBOARDING-HTML-TEAM-UPLOAD-RUNBOOK-AR-17`  
**الهدف**: توضيح الخطوات والضوابط العملية لفريق المحتوى لرفع واختبار واعتماد الموارد التفاعلية (الخرائط الذهنية والتجارب العملية).

---

## 1. شروط وقواعد إعداد حزمة HTML

عند إعداد حزمة موارد HTML، يجب الالتزام الصارم بالشروط الأمنية والفنية التالية:

1. **الهيكل الداخلي للحزمة (ZIP)**:
   - يجب أن تحتوي الحزمة على ملف `index.html` رئيسي.
   - يجب إدراج ملف `manifest.json` يحدد كود المورد والإصدار.
   - جميع المراجع لملفات CSS والصور وJavaScript يجب أن تكون نسبية (Relative Paths).
2. **منع الإحداثيات الخارجية والرابط المباشرة (Fail-Closed Security)**:
   - يمنع استخدام نصوص برمجية من خوادم خارجية (`<script src="https://...">`).
   - يمنع استخدام `eval()` أو `sendBeacon` أو WebRTC.
3. **حظر تسريب الإجابات أو الشروحات (No Answer Key / Explanation Leakage)**:
   - يُمنع تماماً تضمين حقول الإجابات الصحيحة مثل `correct_index` أو `correct_answer` أو `answer_key` أو `explanation` داخل ملفات HTML أو JS أو JSON بالحزمة.
   - الفحص الأمني (Preflight Scanner) يرفض الحزمة تلقائياً وبشكل قاطع عند اكتشاف أي من هذه الكلمات الممنوعة.

---

## 2. خطوات رفع واستيراد المحتوى عبر الواجهة

1. **الخطوة الأولى: إعداد البيانات في ملف Excel**:
   - استخدام قالب استيراد الموارد التفاعلية 06 (`interactive_lesson_resources_template.xlsx`).
   - تحديد كود الدرس (`lesson_code`) وكود المورد (`resource_code`).
2. **الخطوة الثانية: تشغيل الفحص المحلي (Dry-Run Check)**:
   - الانتقال إلى واجهة استيراد المحتوى `/admin/import`.
   - رفع ملف Excel وحزمة ZIP.
   - الضغط على **"تشغيل فحص Dry-Run الشامل"**.
   - مراجعة تقرير الفحص والـ Safe Preview داخل بيئة العزل (Iframe Sandbox).
3. **الخطوة الثالثة: إرسال المورد للمراجعة (Submit for Review)**:
   - بعد اجتياز الفحص بنسبة 100% بدون أي تنبيهات أمنية، يتم حفظ المسودة وإرسالها للمراجعة الإدارية (`in_review`).
4. **الخطوة الرابعة: الاعتماد والنشر (Approve & Publish)**:
   - يقوم مدير النظام (Admin) بفتح واجهة المراجعة `/admin/content-review`.
   - مراجعة المحتوى والتأكد من الفحوصات الأمنية.
   - اتخاذ قرار **الاعتماد (Approve)** ثم **النشر (Publish)**.
   - فور النشر، يصبح المورد متاحاً للطالب داخل صفحة الدرس المحدد حصراً.

---

## 3. التدابير الأمنية وضمان الخصوصية

- **حظر بيئة Capacitor على الهواتف**: تشغيل HTML يبقى معطلاً افتراضياً في Runtime المحمول لحماية التطبيق (Fail-closed).
- **العزل التام (Iframe Sandbox)**: يتم تشغيل المحتوى داخل إطار معزول بتقييد strict CSP.
- **خصخصة التخزين**: حزم HTML تُحفظ داخل Storage Buckets خاصة (`private`) ولا يمكن الوصول إليها إلا عبر Signed URLs قصيرة الأجل وللطلاب المصرح لهم بالدرس فقط.
