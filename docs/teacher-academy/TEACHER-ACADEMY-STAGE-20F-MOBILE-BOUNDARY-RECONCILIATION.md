## سبب فتح Stage 20F

بعد توحيد تطبيق Android تحت اسم «تمكين» وإضافة مسار الأكاديمية، أصبح من الضروري تجميد الحد الفاصل بين تجربتي الطالب والمعلم قبل أي توسع إضافي.

المبدأ المعتمد هنا:

> يجوز أن يكون التطبيق الثنائي واحدًا، ويجوز مشاركة طبقة نقل جلسة Google/PKCE كهوية تقنية، لكن **لا يجوز أن تتحول مساحة الطالب إلى واجهة مختلطة للمعلم، ولا أن ترث الأكاديمية أدوار الطالب أو ملفه أو اشتراكاته أو صلاحيات بنك الأسئلة**.

## حدود الواجهة

### 1. مستوى الدخول العام

يسمح بمدخلين واضحين فقط:

- **دخول الطالب** → `/auth` ثم مساحة الطالب.
- **دخول المعلم** → `/academy` ثم مساحة الأكاديمية.

هذا هو المكان الطبيعي لاختيار نوع التجربة.

### 2. بعد دخول الطالب

مساحة الطالب يجب أن تبقى Student-only:

- لا تعرض قوائم إدارة الأكاديمية.
- لا تعرض أدوار المدرب/مدير المؤسسة/مسؤول الشهادات.
- لا تعرض حالات العقود أو المقاعد أو Entitlements الخاصة بالمعلمين.
- لا تمنح أي Capability للأكاديمية بسبب `student app_role`.
- لا تجعل الانتقال للأكاديمية جزءًا من التنقل الرئيسي الدائم لمساحة الطالب.

إذا احتاج المستخدم نفسه إلى الانتقال بصفته معلمًا، يتم ذلك عبر **تبديل تجربة صريح خارج سياق الطالب** يعيد التحقق من أهلية ملف المعلم، وليس عبر توريث حالة واجهة الطالب.

### 3. بعد دخول المعلم

مساحة الأكاديمية تبقى Teacher-only:

- `/academy` وcallbacks الخاصة بها مستقلة عن `/app` و`/complete-profile`.
- لا تقرأ ملف الطالب لتقرير دور المعلم.
- لا تعتمد على Student wallet أو Student subscription أو Student certificates.
- لا تستخدم `qb_edit` أو `qb_review` أو `qb_publish` ضمن صلاحيات المعلم الاعتيادية.
- لا تكشف روابط Admin داخل بوابة المعلم لغير المصرح لهم.

## سياسة الجلسة المشتركة

يمكن مشاركة session storage على مستوى التطبيق الثنائي فقط وفق الشروط التالية:

1. `auth.users` هوية مشتركة لا أكثر.
2. تحديد persona يتم من مصدر صلاحية مستقل لكل مساحة.
3. وجود ملف طالب لا ينشئ ملف معلم تلقائيًا، والعكس صحيح.
4. تسجيل الدخول كمعلم لا يضيف أو يرفع `student app_role`.
5. تسجيل الدخول كطالب لا يمنح أي Academy capability.
6. deep-link إلى `/academy/*` يعيد فحص أهلية المعلم قبل عرض الصفحة المستهدفة.
7. deep-link إلى `/app/*` يبقى ضمن حراس الطالب ولا يمر عبر حراس الأكاديمية.

## مصفوفة القبول المستهدفة

| الحالة | النتيجة المطلوبة |
|---|---|
| مستخدم طالب فقط يفتح `/academy` | شاشة دخول/أهلية المعلم، بدون إنشاء ملف معلم تلقائي |
| معلم فقط يفتح `/app` | لا يكتسب دور طالب تلقائيًا |
| مستخدم لديه الملفان | اختيار persona صريح، وكل مساحة تقرأ صلاحياتها فقط |
| StudentShell بعد دخول الطالب | لا يحتوي navigation دائمًا لأدوار أو إدارة الأكاديمية |
| AcademyShell | لا يحتوي Student wallet/roles/certificates |
| Android OAuth للمعلم | يعود إلى `/academy` وليس callback الطالب |
| إشعار محاضرة للمعلم | يفتح مسار academy بعد فحص الأهلية |
| رابط Academy Admin | مخفي في واجهة المعلم ويظل guarded عند الوصول المباشر |

## Scoped RBAC — ثابت التصميم

الأدوار المستهدفة لا تُقرأ من Student `app_role`، وتبقى Scoped إلى أحد النطاقات التالية:

- organization
- program
- cohort
- global academy administration عند الضرورة فقط

أي Grant خارج نطاقه يجب أن يفشل Fail-closed.

## Commerce / Entitlements — ثابت التصميم

تظل دورة الأكاديمية منفصلة:

`product → order/contract → entitlement → enrollment → completion → certificate`

ولا يُسمح باستخدام `self_enroll` كبديل دائم عن الاستحقاق عند البرامج المدفوعة أو المؤسسية.

## الشهادات

- لا تعتمد على شهادات الطالب.

- السحب/الإلغاء له حالة واضحة ومراجعة تدقيقية.
