# وثيقة رحلات المستخدم (UX Flows) — بوابة أكاديمية معلم الثانوية (PWA)

- **اسم الوثيقة:** Teacher Academy — User Experience Flows (بوابة المعلمين PWA)
- **معرّف الوثيقة:** `TEACHER-ACADEMY-UX-FLOWS-01`
- **التاريخ:** 2026-08-02
- **الحالة:** DRAFT — بانتظار قرار المالك (Owner)
- **النطاق:** تحليل وتصميم رحلات المستخدم فقط. هذه الوثيقة لا تتضمن كوداً ولا SQL ولا مخطط قاعدة بيانات، وتُبنى عليها وثائق معمارية وتنفيذية لاحقة.

## 0. مقدمة وثوابت التصميم

### 0.1 القرارات المعتمدة (ثابتة، لا تُعاد مناقشتها)

| # | القرار |
|---|--------|
| 1 | تطبيق الطلاب وبوابة المعلمين واجهتان منفصلتان. |
| 2 | الـ Backend والمناهج وبنك الأسئلة والإدارة مشتركة بين الواجهتين. |
| 3 | صلاحيات التدريب (Trainer / Trainee / Program manager …) مستقلة تماماً عن صلاحيات تحرير ومراجعة ونشر أسئلة الطلاب. |
| 4 | البداية PWA للمعلمين، والتحويل إلى تطبيق مستقل قرار لاحق. |

### 0.2 ثوابت التجربة (تسري على كل رحلة)

- **Arabic-first:** كل النصوص بالعربية الفصحى، واجهة RTL كاملة، خطوط عربية واضحة على الأجهزة الضعيفة، والمصطلحات التقنية تُعرض كما هي بالإنجليزية عند الحاجة (مثل Offline، Sync، Rubric).
- **Mobile-first / لمس أولاً:** أهداف اللمس ≥ 44px، أزرار الإجراء الرئيسية في متناول الإبهام، قوائم سفلية (Bottom sheets) بدل القوائم المنبثقة المعقدة، تنقّل رئيسي عبر Bottom navigation بخمسة عناصر كحد أقصى.
- **Weak Internet / Offline-first:** كل رحلة تُصمَّم أولاً لتعمل بلا شبكة أو بشبكة متقطعة؛ المزامنة غير متزامنة (Async sync) مع طابور محلي (Outbox)، وكل شاشة تعرض حالة الاتصال والمزامنة بوضوح.
- **إعلاء المعلومة على الزخرفة:** لا رسوم ثقيلة، ضغط الفيديو والصور، تحميل كسول (Lazy loading)، وحفظ تلقائي متكرر لأي إدخال.
- **حالة الجلسة:** انتهاء الجلسة (Session expiry) لا يفقد المستخدم عمله المحلي؛ يُستأنف من آخر نقطة بعد إعادة الدخول.

### 0.3 الأدوار (Roles) المشمولة في هذه الوثيقة

| الدور | الوصف المختصر |
|-------|----------------|
| Trainee (معلم متدرب) | يلتحق بالبرامج، ينفّذ الوحدات والمهام، يستلم الشهادات. |
| Trainer / Assessor (مدرب/مقيّم) | يراجع المهام المعينة له، يقيّم بالـ Rubric، يكتب Feedback. |
| Program manager | ينشئ البرامج والنسخ (Cohorts)، يعيّن المدربين، يتابع التقدم. |
| School training admin | يتابع معلمي مدرسته الملتحقين بالبرامج. |
| Education office admin | يتابع على مستوى المنطقة/مكتب التعليم. |
| Certificate verifier (مدقق خارجي) | طرف خارجي يتحقق من صحة شهادة دون حساب. |

> **قرار مالك مفتوح (OD-1):** تسمية الأدوار النهائية ومفاتيحها البرمجية (role keys) تُثبَّت في وثيقة RBAC الخاصة بالأكاديمية، وهي هنا بصيغة عمل مؤقتة.

### 0.4 حالات الاتصال المرجعية المستخدمة في كل الرحلات

| الرمز | الحالة |
|------|--------|
| C1 | متصل بشبكة مستقرة. |
| C2 | شبكة ضعيفة/متقطعة (حزم تُفقد، مهلة طويلة). |
| C3 | بلا اتصال (Offline) كلياً. |

## 1. رحلة التسجيل والانضمام وإكمال الملف المهني

### 1.1 الهدف
معلم جديد يفتح البوابة لأول مرة ويصل إلى لوحة تحكم (Dashboard) بملف مهني مكتمل يحدد مدرسته ومادته وصفوفه.

### 1.2 الدخول إلى الرحلة
- عبر رابط دعوة من المدرسة/مكتب التعليم (Deeplink أو QR مطبوع).
- أو بالتسجيل الذاتي من الصفحة الرئيسية للبوابة.

### 1.3 الخطوات

1. فتح رابط البوابة في المتصفح على الجوال؛ تظهر شاشة تعريفية قصيرة (شعار، جملة واحدة، زر «ابدأ») مع عرض تثبيت الـ PWA (Add to Home Screen) بشكل غير مانع.
2. اختيار «إنشاء حساب» أو الدخول عبر الدعوة.
3. إدخال رقم الجوال أو البريد الإلكتروني (قناة التحقق الافتراضية: OTP عبر SMS).
4. إدخال رمز التحقق OTP؛ عند نجاحه تُنشأ الجلسة.
5. شاشة «أكمل ملفك المهني» على مراحل قصيرة (Progressive profiling) كل مرحلة شاشة واحدة:
   1. الاسم الثلاثي + صورة شخصية (اختياري، قابلة للتأجيل).
   2. المنطقة التعليمية → مكتب التعليم → المدرسة (قوائم متسلسلة مع بحث نصي فوري، تعمل من نسخة محلية مضغوطة).
   3. التخصص/المادة + الصفوف التي يدرّسها (Multi-select).
   4. سنوات الخبرة + المؤهل (قوائم جاهزة لتقليل الإدخال الحر).
6. إن كان الدخول بدعوة تتضمن التحاقاً مسبقاً ببرنامج/نسخة (Cohort)، تظهر شاشة «تم إلحاقك ببرنامج …» وإلا تظهر شاشة استكشاف الكتالوج.
7. مؤشر اكتمال الملف (Profile completeness) يظهر في الـ Dashboard حتى بلوغ 100%.
8. الوصول إلى الـ Dashboard.

### 1.4 الحالات الاستثنائية

| الحالة | السلوك المطلوب |
|--------|-----------------|
| تأخر/فقدان OTP (C2/C3) | إعادة إرسال بعد عدّاد 60 ثانية؛ عرض رسالة «تحقق من الشبكة»؛ لا يُفقد ما أُدخل سابقاً. |
| انقطاع أثناء إكمال الملف | حفظ كل مرحلة محلياً فور إتمامها؛ عند العودة يُستأنف من أول مرحلة ناقصة. |
| المدرسة غير موجودة في القائمة | خيار «مدرستي غير موجودة» يفتح نموذج إدخال حر يُرسل كطلب إضافة للإدارة، مع السماح بإكمال التسجيل. |
| رقم جوال مسجل مسبقاً | توجيه لشاشة تسجيل الدخول بدل إنشاء حساب مكرر، مع رسالة واضحة. |
| انتهاء الجلسة لاحقاً | إعادة OTP فقط؛ بيانات الملف المهني محفوظة ولا تُطلب مجدداً. |

### 1.5 متطلبات الواجهة

- لوحة أرقام عربية/إنجليزية لحقل OTP مع لصق تلقائي (Auto-fill) عند دعم المتصفح.
- القوائم المتسلسلة (منطقة → مكتب → مدرسة) بخط عربي كبير وبحث فوري يعمل Offline من بيانات مُخزنة.
- رسائل الخطأ أسفل الحقل مباشرة، بلون واضح لا يعتمد على اللون وحده (أيقونة + نص).

### 1.6 سلوك Offline والمزامنة

- **يعمل بلا شبكة:** استعراض البيانات المخزنة محلياً (المدارس/المناطق)، تعبئة مراحل الملف (تُحفظ في Outbox).
- **ينتظر المزامنة:** إرسال OTP، إنشاء الحساب، الإرسال النهائي للملف المهني.
- **التعارض:** إذا عُدّل الملف من جهاز آخر قبل مزامنة النسخة المحلية، تُطبَّق قاعدة «آخر كتابة تغلب» (Last-write-wins) على مستوى الحقل الواحد، مع إشعار المستخدم بالحقول التي تغيّرت.
- **قرار مالك مفتوح (OD-2):** هل إنشاء الحساب يتطلب اتصالاً إلزامياً (OTP حتمي) أم تُسمح جلسة Offline مؤجلة التفعيل؟ الافتراض التصميمي هنا: OTP إلزامي، فالتسجيل يتطلب C1 أو C2.

## 2. رحلة التشخيص (Diagnostic Assessment)

### 2.1 الهدف
تقييم أولي يحدد مستوى المتدرب ويُوصي بمسار تعلم مناسب.

### 2.2 الدخول
- إلزامي بعد أول التحاق ببرنامج يتطلب تشخيصاً، أو اختياري من بطاقة «حدّد مستواك» في الـ Dashboard.

### 2.3 الخطوات

1. شاشة تمهيدية: الهدف، عدد الأسئلة، الزمن التقديري، تنبيه «يمكنك الإيقاف والاستئناف في أي وقت» + زر «ابدأ التشخيص».
2. عند الضغط على «ابدأ»: يُحمَّل حزم الأسئلة كاملة إلى التخزين المحلي قبل عرض أول سؤال (قابلية Offline كاملة بعد بدء التحميل).
3. شريط تقدّم (سؤال X من Y) مع مؤشر حفظ تلقائي («تم الحفظ ✓») بعد كل إجابة.
4. الإجابة على الأسئلة (اختيار من متعدد أساساً، لمس أولاً بأزرار كبيرة).
5. التنقل للأمام/للخلف بين الأسئلة، مع شاشة مراجعة قبل التسليم تعرض الأسئلة غير المجابة.
6. زر «تسليم»؛ إن كانت الشبكة متاحة يُرسل فوراً، وإلا يُخزَّن في Outbox ويظهر «سيُرسل تلقائياً عند توفر الشبكة».
7. شاشة النتيجة: المستوى العام + خريطة نقاط القوة/الضعف حسب المحاور، دون إظهار الأسئلة الصحيحة/الخاطئة تفصيلياً (تشخيص وليس اختباراً).
8. بطاقة «المسار الموصى به» مع زر «التحق بالمسار الموصى» أو «تصفح الكتالوج كاملاً».

### 2.4 الاستئناف بعد انقطاع

- أي خروج (إغلاق التطبيق، مكالمة، انقطاع كهرباء) يُحفظ عنده: رقم السؤال الحالي، الإجابات المختارة، الزمن المنقضي.
- عند العودة تظهر بطاقة «لديك تشخيص غير مكتمل — استئناف من السؤال N» في الـ Dashboard وداخل شاشة التشخيص.
- **قرار مالك مفتوح (OD-3):** مدة صلاحية جلسة التشخيص غير المكتمل (مثلاً 7 أيام) قبل اعتبارها ملغاة وإتاحة البدء من جديد.

### 2.5 الحالات الاستثنائية

| الحالة | السلوك |
|--------|--------|
| انقطاع أثناء تحميل حزمة الأسئلة (الخطوة 2) | استئناف التحميل من نقطة التوقف (Resumable download)؛ لا يبدأ التشخيص قبل اكتمال الحزمة. |
| تسليم بلا شبكة | التسليم يبقى «بانتظار المزامنة»؛ شاشة النتيجة تعرض الحالة «نتيجتك قيد الحساب» حتى التأكيد من الخادم. |
| تشخيص سابق مكتمل | إعادة التشخيص مسموحة فقط بفاصل زمني (قرار مالك مفتوح OD-4، الافتراض 30 يوماً) أو بإعادة تعيين من Program manager. |
| انتهاء الجلسة | الإجابات محلية؛ بعد إعادة الدخول يُستأنف ويُزامَن. |

### 2.6 متطلبات الواجهة

- سؤال واحد لكل شاشة على الجوال، خيارات بعرض كامل، دعم صور/معادلات داخل الأسئلة بضغط عالٍ.
- شريط التقدم ثابت أعلى الشاشة، وزر التسليم لا يظهر إلا في شاشة المراجعة لتفادي التسليم العرضي.

### 2.7 سلوك Offline والمزامنة

- **يعمل بلا شبكة:** الإجابة على كل الأسئلة بعد اكتمال التحميل، الاستئناف، المراجعة قبل التسليم.
- **ينتظر المزامنة:** التسليم النهائي وحساب النتيجة (الحساب على الخادم لمنع التلاعب)، وتوصية المسار.
- **التعارض:** التشخيص يُسلَّم مرة واحدة؛ أي محاولة تسليم مكررة بعد نجاح الأولى تُرفض بإشعار «تم تسليم تشخيصك مسبقاً».

## 3. رحلة التعلم (Learning Journey)

### 3.1 الهدف
تصفح الكتالوج، الالتحاق بمسار، استهلاك وحدات (فيديو/قراءة/نشاط/اختبار) مع دعم Offline كامل للوحدات المنزّلة.

### 3.2 تصفح الكتالوج والالتحاق

1. من تبويب «الكتالوج»: قائمة مسارات ببطاقات (العنوان، عدد الوحدات، المدة التقديرية، المستوى، شارة «موصى به» إن وُجد تشخيص).
2. فلاتر بسيطة: المادة، المستوى، الحالة (جديد/قيد التقدم/مكتمل).
3. صفحة المسار: وصف، مخرجات التعلم، قائمة الوحدات والأنشطة، متطلبات الشهادة، زر «التحق بالمسار».
4. الالتحاق يتطلب اتصالاً (C1/C2) لتثبيت الـ Enrollment على الخادم؛ بعده تُزامَن بنية المسار (العناوين والبيانات الوصفية) للعرض Offline.
5. تظهر المسارات الملتحق بها في تبويب «تعلّمي» مع نسبة إنجاز لكل مسار.

### 3.3 تنزيل وحدة Offline

1. بجانب كل وحدة زر «تنزيل» مع حجم التنزيل المتوقع.
2. عند الضغط: تنزيل مجزأ (Chunked) قابل للاستئناف، مع مؤشر تقدم وخيار «إيقاف مؤقت».
3. بعد الاكتمال تظهر شارة «متاح Offline» وتُدار المساحة من شاشة «التنزيلات» (حذف يدوي، وعرض المساحة المستهلكة).
4. تحميل تلقائي اختياري للوحدة التالية عند توفر Wi-Fi (إعداد قابل للإطفاء).

### 3.4 مشاهدة فيديو مع استئناف الموضع

1. فتح درس الفيديو؛ إن كان منزّلاً يُشغَّل محلياً وإلا يُبث بجودة تكيفية (Adaptive) مع خيار يدوي للجودة المنخفضة.
2. حفظ موضع المشاهدة تلقائياً كل ~10 ثوانٍ محلياً فوراً، ومزامنته مع الخادم عند توفر الشبكة.
3. عند العودة لاحقاً: «استئناف من 07:42» أو «بدء من جديد».
4. عند بلوغ عتبة الإكمال (الافتراض 90% — قرار مالك مفتوح OD-5) تُعلَّم الوحدة كمكتملة وتظهر شارة إنجاز.

### 3.5 إكمال نشاط واختبار وحدة (Quiz)

1. النشاط التفاعلي (مثلاً بطاقات/سحب وإفلات مبسطة) يعمل Offline بالكامل بعد تنزيل الوحدة؛ النتيجة تُحفظ محلياً وتُزامَن.
2. اختبار الوحدة يتبع نفس نمط التشخيص (تحميل كامل مسبق، حفظ تلقائي، تسليم عبر Outbox).
3. عتبة النجاح لكل اختبار معلنة مسبقاً؛ إعادة المحاولة مسموحة بعد انتهاء مهلة (Cooldown) موضحة على الشاشة.
4. بعد الإكمال تظهر شاشة «أحسنت» مع الخطوة التالية المقترحة.

### 3.6 الحالات الاستثنائية

| الحالة | السلوك |
|--------|--------|
| مساحة التخزين ممتلئة أثناء التنزيل | إيقاف التنزيل برسالة واضحة + رابط لشاشة إدارة التنزيلات. |
| انقطاع أثناء بث الفيديو (C2) | خفض الجودة تلقائياً؛ إن تعذّر الاستمرار يُقترح تنزيل الوحدة للمشاهدة Offline. |
| تعارض موضع المشاهدة بين جهازين | يُعتمد الموضع الأبعد زمنياً (الأحدث timestamp)؛ لا يُسأل المستخدم. |
| محتوى وحدة تحدّث بعد تنزيلها | شارة «تحديث متاح» على الوحدة؛ المحتوى القديم يبقى قابلاً للمشاهدة حتى يُحدَّث. |

### 3.7 متطلبات الواجهة

- تبويبات سفلية: الرئيسية / تعلّمي / الكتالوج / التنزيلات / حسابي.
- مشغل فيديو بأزرار كبيرة، دعم ملء الشاشة بالوضع الأفقي، وسرعات تشغيل (1×–1.5×–2×).
- نسب الإنجاز مرئية دائماً (Progress rings على البطاقات).

### 3.8 سلوك Offline والمزامنة

- **يعمل بلا شبكة:** تصفح الوحدات المنزلة وبيانات المسارات المتزامنة، مشاهدة الفيديو المنزل، الأنشطة واختبارات الوحدات المنزلة، تسجيل التقدم.
- **ينتظر المزامنة:** الالتحاق بمسار جديد، تسليم الاختبارات، مزامنة `module_progress` ومواضع المشاهدة.
- **التعارض:** `module_progress` قابل للدمج (القيمة الأعلى تغلب للنسب المئوية، والأحدث لمواضع الفيديو)؛ تسليم الاختبارات الأول-يُقبل.

## 4. رحلة المهمة التطبيقية (Practical Assignment)

### 4.1 الهدف
تنفيذ مهمة صفية واقعية، ورفع دليل التنفيذ (صور/ملف مضغوط) للمراجعة، واستلام تقييم Rubric وFeedback، مع إمكانية الاعتراض وإعادة التسليم.

### 4.2 الخطوات

1. داخل المسار، وحدة «مهمة تطبيقية» تعرض: وصف المهمة، معايير الـ Rubric كاملة قبل التنفيذ (شفافية التقييم)، الموعد النهائي إن وُجد، وصيغ الدليل المقبولة (صور JPG/PNG أو ملف مضغوط ZIP بحد أقصى للحجم).
2. زر «بدء التنفيذ» يغيّر حالة المهمة إلى «قيد التنفيذ» (تُحفظ محلياً وتُزامَن).
3. ينفّذ المعلم المهمة في صفه (خارج التطبيق غالباً — قد يكون بلا شبكة لأيام).
4. عند توفر الدليل: شاشة رفع تدعم التقاط صور من الكاميرا مباشرة (مع ضغط تلقائي) أو اختيار ملف مضغوط، مع معاينة قبل الإرفاق وإمكانية حذف مرفق.
5. المرفقات تُخزَّن محلياً أولاً (Draft submission) وتبقى قابلة للتعديل حتى الضغط على «تسليم».
6. عند «تسليم»: تُرفع الملفات مجزأة قابلة للاستئناف؛ إن لم تتوفر شبكة تدخل طابور Outbox بحالة «بانتظار الرفع» مع مؤشر دائم في التطبيق.
7. بعد اكتمال الرفع تتحول الحالة إلى «قيد المراجعة» وتظهر المدة المتوقعة للمراجعة.
8. عند انتهاء المراجعة: إشعار (Push إن فُعّل، وإلا بطاقة في الـ Dashboard) مع النتيجة: «مقبول» أو «معاد للتحسين».
9. شاشة النتيجة تعرض درجات الـ Rubric بنداً ببنداً + Feedback نصي من المدرب.
10. عند «معاد للتحسين»: زر «إعادة التسليم» يفتح مسودة جديدة مبنية على السابقة (المرفقات القديمة قابلة للاستبدال أو الإبقاء)، وتاريخ التسليمات السابقة يبقى مرئياً.
11. عند اعتراض على التقييم: زر «اعتراض» يفتح نموذجاً نصياً قصيراً يُرسل لمدرب آخر/للجنة (وفق سياسة البرنامج).

### 4.3 الحالات الاستثنائية

| الحالة | السلوك |
|--------|--------|
| رفع فشل منتصف الطريق (C2) | استئناف تلقائي من آخر جزء ناجح؛ لا تُفقد المرفقات المحلية إلا بحذف يدوي. |
| ملف يتجاوز الحد الأقصى | رفض قبل بدء الرفع مع رسالة بالحجم المسموح واقتراح ضغط الملف. |
| رفض مراجعة متكرر | بعد N إعادة تسليم (قرار مالك مفتوح OD-6، الافتراض 3) تُحوَّل المهمة للمدرب للتواصل المباشر/جلسة دعم. |
| انتهاء الموعد النهائي | المهمة تبقى قابلة للتسليم بعلامة «متأخر» ما لم يُغلقها Program manager (قرار مالك مفتوح OD-7). |
| الاعتراض مرفوض | إشعار بقرار نهائي مع تلخيص المبرر؛ لا اعتراض ثانٍ على نفس التسليم. |
| انتهاء الجلسة أثناء الرفع | الرفع المحلي مستمر بعد إعادة الدخول (الملفات محلية، والـ Tokens تُجدَّد). |

### 4.4 متطلبات الواجهة

- عرض الـ Rubric قبل التنفيذ وبعد التقييم بنفس البنية البصرية (جدول معايير × مستويات) ليقابل المعلم بين المتوقع والمُقيَّم.
- شاشة الرفع بعدّاد مرفقات وأحجامها، ومعاينات مصغرة للصور.
- خط زمني (Timeline) لحالة المهمة: بدأت → سلّمت → قيد المراجعة → مقبول/معاد.

### 4.5 سلوك Offline والمزامنة

- **يعمل بلا شبكة:** قراءة المهمة والـ Rubric، بدء التنفيذ، تجهيز المسودة والمرفقات، تصفح تاريخ التسليمات المتزامن.
- **ينتظر المزامنة:** التسليم الفعلي، استلام حالة المراجعة والـ Feedback، إرسال الاعتراض.
- **التعارض:** تسليم واحد نشط لكل مهمة؛ بدء مسودة إعادة تسليم يمنع فتح مسودة موازية على جهاز آخر (قفل منطقي عند أول مزامنة، مع رسالة توضح الجهاز/الجلسة المالكة للمسودة).

## 5. رحلة الشهادة (Certification)

### 5.1 الهدف
استيفاء شروط برنامج، إتمام المشروع الختامي، استلام شهادة قابلة للتحقق (رمز + QR)، ومشاركتها، مع رحلة مستقلة لمدقق خارجي.

### 5.2 الخطوات (المتدرب)

1. بطاقة «شهادتك» في صفحة المسار تعرض الشروط ونسبة استيفاء كل منها: إكمال الوحدات، اجتياز اختبارات الوحدات، قبول المهام التطبيقية، المشروع الختامي.
2. عند استيفاء الشروط الأولية تُفتح «المهمة الختامية» (Capstone) وتتبع رحلة المهمة التطبيقية (القسم 4) بمعايير Rubric ختامية.
3. بعد قبول المشروع الختامي: إشعار «تهانينا، شهادتك جاهزة».
4. شاشة الشهادة: الاسم كما في الملف المهني (مع تنبيه لتصحيحه قبل الإصدار إن لزم)، اسم البرنامج، تاريخ الإصدار، رمز تحقق نصي قصير، ورمز QR.
5. أزرار: «تنزيل PDF»، «مشاركة رابط التحقق»، «مشاركة الصورة» (للشبكات الاجتماعية).
6. الشهادة تُخزَّن محلياً للعرض Offline ضمن تبويب «حسابي ← شهاداتي».

### 5.3 رحلة المدقق الخارجي (Certificate verifier)

1. فتح صفحة تحقق عامة (لا تتطلب حساباً) عبر مسح الـ QR أو إدخال رمز التحقق يدوياً.
2. إدخال الرمز → تحقق من الخادم (يتطلب اتصالاً).
3. عرض نتيجة التحقق: صالحة/غير صالحة، اسم حاملها، البرنامج، تاريخ الإصدار، حالة الشهادة (نشطة/ملغاة).
4. لا تُعرض أي بيانات إضافية عن المتدرب (درجات، مدرسة) حمايةً للخصوصية.
5. رمز غير موجود أو شهادة ملغاة → رسالة واضحة دون كشف سبب تفصيلي للغاية.

### 5.4 الحالات الاستثنائية

| الحالة | السلوك |
|--------|--------|
| خطأ في الاسم بعد الإصدار | طلب تصحيح يُرسل للإدارة؛ الإصدار المصحح يحمل نفس رمز التحقق (قرار مالك مفتوح OD-8: هل التصحيح يلغي الرمز القديم ويصدر رمزاً جديداً؟). |
| المدقق بلا شبكة | التحقق يتطلب اتصالاً؛ تظهر رسالة «التحقق يحتاج اتصالاً بالإنترنت» (الـ QR نفسه يحمل الرابط فقط). |
| إلغاء شهادة (مخالفة) | صفحة التحقق تعرض «ملغاة»؛ المتدرب يُشعَر في التطبيق. |
| فقدان رمز التحقق | المتدرب يسترجعه دائماً من «شهاداتي»؛ لا إعادة إصدار لازمة. |

### 5.5 متطلبات الواجهة

- شاشة الشهادة قابلة للمشاركة بصيغة صورة مهيأة (RTL صحيح في التصدير، خط عربي مضمّن في PDF).
- صفحة التحقق العامة خفيفة جداً (صفحة واحدة، حقل واحد، زر واحد) وتعمل على أي متصفح.

### 5.6 سلوك Offline والمزامنة

- **يعمل بلا شبكة:** عرض الشهادات المتزامنة ورموزها وQR.
- **ينتظر المزامنة:** إصدار الشهادة (خادم فقط)، التحقق الخارجي، التنزيل الأول للـ PDF إن لم يُخزن.
- **التعارض:** لا تعارض للمستخدم؛ حالة الشهادة (نشطة/ملغاة) تُحسم من الخادم عند كل تحقق.

## 6. رحلة المدرب/المقيّم (Trainer / Assessor)

### 6.1 الهدف
مراجعة المهام المعينة، التقييم بالـ Rubric، كتابة Feedback واضح، وإعادة المهمة للمتدرب عند الحاجة.

### 6.2 الخطوات

1. تبويب «المراجعة» يعرض قائمة التسليمات المعينة مرتبة بالأقدم، مع مرشحات: البرنامج/النسخة، حالة المراجعة (جديد/قيد المراجعة/أُنجز)، وعدد أيام الانتظار (لإبراز المتأخر).
2. بطاقة التسليم تعرض: اسم المتدرب، البرنامج والمهمة، تاريخ التسليم، رقم المحاولة (تسليم أول/إعادة N).
3. فتح التسليم: عرض الدليل (صور بمعرض داخلي، محتوى الملف المضغوط بقائمة ملفات مع عارض للصور وPDF)، ووصف المهمة، والـ Rubric.
4. التقييم: اختيار مستوى كل بند في الـ Rubric (لمس أولاً)، مع حفظ تلقائي لمسودة التقييم محلياً.
5. حقل Feedback نصي إلزامي عند «إعادة للتحسين» (اختياري لكن مشجَّع عند القبول)، مع إرشادات قصيرة لكتابة Feedback بنّاء.
6. قرار المراجعة: «قبول» أو «إعادة للتحسين»؛ شاشة تأكيد تلخّص الدرجات قبل الإرسال النهائي.
7. الإرسال يُزامَن فوراً عند توفر الشبكة وإلا يدخل Outbox بحالة «مراجعة بانتظار الإرسال».
8. بعد الإرسال يُشعَر المتدرب، وتنتقل المراجعة إلى سجل «المنجزة».
9. الاعتراضات الواردة على تقييماته تظهر في قائمة منفصلة «اعتراضات» مع مهلة للرد (قرار مالك مفتوح OD-9: من يرد على الاعتراض — نفس المدرب أم مقيّم مستقل؟ الافتراض التصميمي: مقيّم مستقل يعينه Program manager).

### 6.3 الحالات الاستثنائية

| الحالة | السلوك |
|--------|--------|
| فتح تسليم من جهازين | مسودة التقييم محلية لكل جهاز؛ عند الإرسال الأول تُقفل المراجعة، والإرسال الثاني يُرفض برسالة «أُرسلت هذه المراجعة مسبقاً». |
| مرفق لا يفتح (تالف/صيغة غير مدعومة) | يمكن للمدرب إعادة المهمة بسبب «دليل غير قابل للقراءة» مع توضيح إلزامي. |
| تجاوز مهلة المراجعة (SLA) | تصعيد تلقائي يظهر لدى Program manager (قرار مالك مفتوح OD-10: مدة الـ SLA — الافتراض 7 أيام). |
| انقطاع أثناء كتابة تقييم طويل | المسودة محلية ولا تُفقد؛ تُستأنف من نفس النقطة. |

### 6.4 متطلبات الواجهة

- شاشة التقييم بتقسيم عمودي على الشاشات الكبيرة (الدليل يميناً/الـ Rubric يساراً بما يناسب RTL) وبتبويبات متبدلة على الجوال.
- عدّاد «متبقٍ للمراجعة» بارز لتشجيع إنجاز الطابور.

### 6.5 سلوك Offline والمزامنة

- **يعمل بلا شبكة:** تصفح التسليمات التي سبق تنزيل أدلتها، تعبئة مسودات التقييم والـ Feedback.
- **ينتظر المزامنة:** تنزيل أدلة جديدة، الإرسال النهائي للمراجعة، استلام الاعتراضات.
- **التعارض:** أول إرسال ناجح يُقفل المراجعة؛ مسودات الأجهزة الأخرى تُهمَل مع إشعار واضح.

## 7. رحلات الإدارة (Admin Flows)

### 7.1 Program manager — إنشاء برنامج ونسخة وتعيين مدربين

1. من لوحة الإدارة: «برنامج جديد» — نموذج متعدد الخطوات: الاسم والوصف، المستوى والفئة المستهدفة، بنية المسار (ربط وحدات من المحتوى المشترك)، شروط الشهادة، ومعايير الـ Rubric للمهام والمشروع الختامي.
2. حفظ كمسودة (Draft) مع معاينة كما سيراها المتدرب.
3. «نشر» البرنامج (يتطلب اتصالاً) ليصبح ظاهراً في الكتالوج حسب سياسة الظهور (عام/بدعوة فقط).
4. إنشاء نسخة (Cohort) من البرنامج: اسم النسخة، نطاق الاستهداف (منطقة/مكتب/مدارس)، تواريخ البدء والانتهاء، سعة اختيارية.
5. تعيين مدربين على النسخة: بحث بالاسم/الرقم، تحديد نطاق كل مدرب (كل النسخة أو مجموعة متدربين)، مع عرض عبء العمل الحالي لكل مدرب (عدد التسليمات المعلقة).
6. لوحة متابعة: نسب الالتحاق والإكمال، طابور المراجعات المتأخرة، إعادة تعيين تسليمات من مدرب متجاوز للـ SLA إلى آخر.
7. الرد على الاعتراضات (تعيين مقيّم مستقل) وطلبات إضافة المدارس (من القسم 1.4).

**الحالات الاستثنائية:** تعديل برنامج منشور له ملتحقون → التعديلات البنيوية الجوهرية تُنشئ إصداراً جديداً ولا تؤثر بأثر رجعي على المنخرطين (قرار مالك مفتوح OD-11: سياسة ترحيل الملتحقين الحاليين للإصدار الجديد). حذف نسخة بها متدربون نشطون → ممنوع؛ أرشفة فقط.

### 7.2 School training admin — متابعة معلمي مدرسته

1. لوحة «مدرستي»: قائمة معلمي المدرسة المسجلين في البوابة مع حالة كل منهم (مسجل/لم يكمل الملف/نشط في برنامج).
2. لكل معلم: البرامج الملتحق بها، نسب الإنجاز، المهام المتأخرة، الشهادات المحصلة.
3. إجراءات: إرسال تذكير (Notification) لمعلم متأخر، تصدير تقرير CSV/ملخص PDF لمدير المدرسة.
4. دعوة معلمين جدد: توليد رابط/QR دعوة خاص بالمدرسة.
5. **لا يرى** محتوى إجابات المتدربين ولا تفاصيل تقييمات الـ Rubric (نطاق الرؤية: تقدم وحالات فقط) — قرار مالك مفتوح OD-12: هل يحق له الاطلاع على درجات التشخيص التجميعية لمعلميه؟

**Offline:** اللوحة تعرض آخر نسخة متزامنة مع ختم «آخر تحديث: …»؛ الإجراءات (تذكير/دعوة/تصدير) تتطلب اتصالاً.

### 7.3 Education office admin — متابعة على مستوى المنطقة

1. لوحة المنطقة: مؤشرات تجميعية (عدد المعلمين النشطين، نسب الإكمال حسب المدرسة/البرنامج، خريطة تقدم النسخ).
2. التعمق (Drill-down): منطقة ← مدرسة ← قائمة معلمين (بنفس نطاق رؤية School training admin).
3. تقارير دورية مجدولة ومقارنات بين المدارس/النسخ.
4. لا صلاحية تحرير على المحتوى أو التقييمات — دور رقابي/متابعة.

**الحالات الاستثنائية:** مدرسة بلا أي نشاط لفترة → تنبيه في اللوحة. بيانات قديمة Offline → ختم زمني إلزامي على كل لوحة.

### 7.4 متطلبات الواجهة للإدارة

- لوحات الإدارة تعمل على الجوال لكنها مهيأة أيضاً للأجهزة اللوحية/سطح المكتب (جداول قابلة للتمرير الأفقي، مرشحات لاصقة).
- كل جدول يدعم تصديراً خفيفاً وطباعة ملخص عربي RTL سليم.

## 8. مصفوفة سلوك Offline/المزامنة الموحّدة

| العنصر | يعمل Offline (C3) | ينتظر المزامنة | سياسة التعارض |
|--------|-------------------|-----------------|----------------|
| الملف المهني | تعبئة وحفظ محلي | الإرسال النهائي | Last-write-wins على مستوى الحقل |
| التشخيص | الإجابة الكاملة بعد تحميل الحزمة | التسليم وحساب النتيجة | أول تسليم يُقبل |
| تقدم الوحدات `module_progress` | تسجيل محلي كامل | مزامنة الخادم | دمج: الأعلى للنسب، الأحدث لمواضع الفيديو |
| اختبارات الوحدات | الإجابة بعد التحميل | التسليم | أول تسليم يُقبل |
| المهام التطبيقية | مسودة + مرفقات محلية | الرفع والتسليم واستلام النتيجة | تسليم نشط واحد؛ قفل مسودة |
| مراجعات المدرب | مسودة التقييم | الإرسال النهائي | أول إرسال يُقفل المراجعة |
| الشهادات | العرض والـ QR | الإصدار والتحقق | حالة الخادم حاسمة |
| الالتحاق بالمسارات | — | دائماً يتطلب اتصالاً | — |
| لوحات الإدارة | عرض آخر مزامنة بختم زمني | كل الإجراءات والتقارير | قراءة فقط Offline |

**قواعد عامة للمزامنة:**
- كل عملية معلقة تظهر في مركز مزامنة موحد (Sync center) بحالة واضحة وزر «إعادة المحاولة».
- فشل متكرر (أكثر من N محاولات — قرار مالك مفتوح OD-13، الافتراض 5) ينقل العملية لحالة «تتطلب تدخلك» مع شرح السبب.
- لا يُحذف أي عمل محلي معلق تلقائياً؛ الحذف يدوي فقط وبعد تحذير.
