# أكاديمية تمكين للمعلمين — دليل إطلاق الـMVP

## 1. النطاق الثابت

- تطبيق ويب مستقل داخل المستودع في `apps/teacher-academy`.
- قاعدة البيانات في مخطط `academy`، مع مشاركة `auth.users` وجدول المحافظات فقط.
- التسجيل ذاتي بلا دعوات أو اعتماد يدوي.
- الملف المهني الإلزامي: الاسم، المادة الأساسية، المحافظة، المدرسة، الهاتف.
- الكتالوج يظهر البرامج العامة وبرامج مادة المعلم فقط، ويطبق ذلك من الخادم.
- رحلة المعلم: ملف مهني ← كتالوج ← تسجيل ← دروس ← تقييم ← شهادة.
- لوحة الإدارة بصلاحيات أكاديمية مستقلة للبرامج والمعلمين والتقدم والشهادات.

خارج هذا الإصدار: المدفوعات، المؤسسات، المدربون، الموافقات اليدوية، الذكاء الاصطناعي، التحليلات المتقدمة، العمل دون اتصال، وربط بنك أسئلة الطلاب.

## 2. بوابات القرار

| البوابة        | شرط PASS                                                                           |
| -------------- | ---------------------------------------------------------------------------------- |
| المصدر         | `npm run academy:test` و`npm run academy:typecheck` و`npm run academy:build` ناجحة |
| قاعدة البيانات | عقد PostgreSQL 17 في CI ناجح على قاعدة نظيفة                                       |
| التجهيز        | فحص ما قبل الإنتاج يثبت قاعدة البيانات وحساب المسؤول وعدم وجود مخطط جزئي           |
| ما بعد التطبيق | RLS والمنح والبذور وصلاحيات المسؤول كلها ناجحة                                     |
| التجربة        | حالات المعلم والإدارة والتحقق من الشهادة ناجحة على staging                         |
| الإطلاق        | النطاق يعمل و`VITE_ACADEMY_ENABLED=true` بعد نجاح جميع ما سبق فقط                  |

أي فشل يعني `HOLD`. لا تُطبق خطوات لاحقة على بيئة الإنتاج.

## 3. متغيرات البناء

انسخ القيم الموضحة في `apps/teacher-academy/.env.example` إلى إعدادات مشروع الاستضافة:

```text
VITE_ACADEMY_ENABLED=false
VITE_SUPABASE_URL=https://<project-ref>.supabase.co
VITE_SUPABASE_PUBLISHABLE_KEY=<publishable-key>
```

يبقى المفتاح `false` أثناء تطبيق القاعدة والتحقق. في بناء الإنتاج لا تُفتح الأكاديمية إلا إذا كانت القيمة `true` حرفيًا.

## 4. فحص ما قبل التطبيق

من جهاز تشغيل موثوق يملك اتصالًا مباشرًا بقاعدة Supabase:

```bash
psql "$SUPABASE_DB_URL" \
  --set=ON_ERROR_STOP=1 \
  --set=academy_admin_email='admin@example.com' \
  --file scripts/teacher-academy/prod-preflight.sql
```

يجب التأكد يدويًا أيضًا من أن `supabase/config.toml` يعرض مخطط `academy` ضمن `api.schemas`، وأن رابط المشروع هو مشروع تمكين الصحيح.

## 5. التطبيق المتحكم به

بعد PASS فقط، طبّق الهجرات بالترتيب التالي عبر آلية هجرات Supabase المعتمدة للمشروع:

1. `20260830020000_teacher_academy_mvp_foundation.sql`
2. `20260830030000_teacher_academy_mvp_learning.sql`
3. `20260830040000_teacher_academy_mvp_assessment_certificates.sql`

لا تُنفذ ملفات الهجرة يدويًا إذا كان المشروع يعتمد سجل `supabase_migrations`; استخدم `supabase db push` من نسخة المستودع نفسها حتى يبقى السجل صحيحًا.

## 6. فحص ما بعد التطبيق

```bash
psql "$SUPABASE_DB_URL" \
  --set=ON_ERROR_STOP=1 \
  --set=academy_admin_email='admin@example.com' \
  --file scripts/teacher-academy/prod-postverify.sql
```

هذا الفحص يثبت RLS على الجداول الخمسة عشر، عدم وجود منح جداول لـ`anon`، المواد التسع، الدوال الأساسية، ويمنح مسؤول الأكاديمية الصلاحيات الثلاث المستقلة بطريقة idempotent.

## 7. بناء ونشر التطبيق المستقل

```bash
npm ci
npm run academy:test
npm run academy:typecheck
npm run academy:build
```

- مجلد النشر: `dist-academy`.
- يجب تفعيل SPA fallback إلى `index.html`، خصوصًا للمسار `/verify`.
- النطاق المستهدف: `academy.studentamkeen.com`.
- ابدأ بـ`VITE_ACADEMY_ENABLED=false`، ثم نفذ تجربة staging، وبعد PASS أعد البناء بالقيمة `true` وانشر النسخة نفسها.

## 8. تجربة القبول المختصرة

1. ينشئ معلم رياضيات حسابًا ويُجبر على استكمال الحقول الخمسة.
2. يرى برنامج الرياضيات والبرامج العامة، ولا يرى برنامج الإنجليزية.
3. يسجل في البرنامج ويكمل الدروس؛ لا يفتح التقييم قبل إكمالها.
4. لا تُرسل الإجابة الصحيحة إلى المتصفح، ويصحح الخادم المحاولة.
5. عند النجاح تصدر شهادة واحدة برمز `TAM-...`، ويمكن التحقق منها عبر `/verify?code=...`.
6. معلم الإنجليزية لا يرى برنامج الرياضيات.
7. مسؤول البرامج ينشئ مسودة ومحتوى وتقييمًا وينشرها، ولا يرث الوصول من أدوار تطبيق الطلاب.
8. مسؤول المعلمين يوقف حسابًا؛ يتعذر عليه استخدام الكتالوج والتعلم فورًا.
9. مسؤول التقدم يرى الإنجاز ويلغي شهادة بسبب مسجل؛ صفحة التحقق تعرضها ملغاة.

## 9. الإيقاف والتعافي

- الإيقاف الفوري القابل للعكس: أعد البناء والنشر مع `VITE_ACADEMY_ENABLED=false`.
- لا تُسقط مخطط `academy` بعد بدء استقبال بيانات حقيقية.
- عند فشل هجرة داخل المعاملة ستتراجع تلقائيًا. عند فشل التحقق بعد نجاح الهجرة، أبقِ الواجهة مغلقة، أصلح بإضافة هجرة تصحيحية، ثم أعد الفحص.
- لا يؤثر الإيقاف على تطبيق الطلاب لأن البناء والمخطط وصلاحيات الإدارة منفصلة.

## 10. سجل الإطلاق

يُحفظ مع كل إطلاق: SHA، ناتج CI، وقت تطبيق الهجرات، نتيجة preflight/postverify، حساب المسؤول المستخدم، رابط staging، وحالات smoke التسع. لا يُعلن الإطلاق دون هذه الأدلة.
