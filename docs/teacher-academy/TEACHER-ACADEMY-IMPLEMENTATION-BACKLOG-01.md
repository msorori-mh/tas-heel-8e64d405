## 2. تعريف MVP الدقيق

هدف MVP: معلم يسجّل → يُشخَّص → يُسنَد له مسار → يدرس وحدات (فيديو + محتوى) → يجتاز اختبارات ومهام بأدلة → يُقيَّم عبر Rubric → يحصل على شهادة قابلة للتحقق — مع لوحة إدارة أساسية. كل ذلك PWA عربي RTL أولاً.

### 2.1 ما يدخل MVP وما يُؤجَّل

| المكوّن | داخل MVP | مؤجَّل (المرحلة) | مبرر الاستبعاد من MVP |
|---|---|---|---|
| التشخيص | تشخيص إلزامي أولي (Diagnostic) يبني خريطة إتقان لكل كفاية ويقترح مساراً؛ إعادة تشخيص واحدة بعد إتمام المسار | تشخيص تكيفي متعدد الجولات (P1)، تشخيص بالذكاء الاصطناعي (P2) | التكيفية تتطلب بنك مفردات مُعايَر ونمذجة IRT غير متوفرة بعد؛ جولة واحدة تكفي لإثبات القيمة |
| المسارات | مسارات خطية مؤلفة من وحدات مرتبة؛ إسناد تلقائي بناءً على التشخيص + إسناد يدوي من الإدارة | مسارات متفرعة بشروط (P1)، توصيات ذكية (P2) | التفريع يضيف محرك قواعد وواجهات بناء معقدة؛ الخطي يغطي منهج التدريب الحالي |
| الوحدات | وحدة = دروس (فيديو + نص + مرفقات) + تقدّم `module_progress`؛ إتمام تلقائي عند استيفاء الدروس | وحدات تفاعلية SCORM/xAPI (P2) | دعم SCORM عبء تشغيلي كبير ولا محتوى جاهزاً به |
| الاختبارات | Quiz لكل وحدة + اختبار نهائي لكل مسار؛ MCQ/صح-خطأ/نص قصير؛ تصحيح آلي؛ حد محاولات | أسئلة مقالية مصححة آلياً (P1)، اختبارات موقوتة بمراقبة Proctoring (P2) | المقالي الآلي يتطلب نماذج لغوية عربية غير مُتحقق منها؛ الـ Proctoring قرار خصوصية/تشغيل |
| المهام | مهمة عملية لكل مسار مع رفع أدلة (PDF/صورة/فيديو قصير) حتى حد حجم محدد | مهام جماعية (P1)، أدلة صوتية طويلة (P2) | الجماعية تتطلب إدارة مجموعات وتقييم أقران خارج نطاق MVP |
| التقييم | مراجعة بشرية عبر Rubric بمعايير مسماة ودرجات رقمية؛ مقيّم واحد لكل تسليم؛ تعليق مكتوب إلزامي عند الرسوب | تقييم مزدوج مستقل + تحكيم ثالث (P1)، تقييم أقران (P2) | التقييم المزدوج يضاعف عبء المقيّمين قبل إثبات حجم الطلب |

| لوحة الإدارة | إدارة مستخدمين وأدوار TA، CRUD مسارات/وحدات/اختبارات/مهام/Rubrics، طابور مراجعة، إصدار/إبطال شهادات، تقارير أساسية (تسجيل/إتمام/اجتياز) | تحرير WYSIWYG متقدم للمحتوى (P1)، لوحات BI قابلة للتخصيص (P2) | التقارير الأساسية تكفي للتشغيل؛ الـ BI يُبنى بعد تراكم بيانات فعلية |

| التكاملات | قراءة المناهج المشتركة، إعادة استخدام بنك الأسئلة في اختبارات TA عبر طبقة اختيار، ربط المعلم بمدرسة/منطقة | استيراد تلقائي لأسئلة الطلاب إلى اختبارات TA (P1)، Analytics موحدة عبر الواجهتين (P1) | الاستيراد الآلي يتطلب سياسات إعادة استخدام وAudit إضافي |
| التوطين | عربي أولاً RTL كامل لكل شاشات MVP | إنجليزي LTR (P1) | الجمهور الحالي عربي؛ الإنجليزي توسعة لاحقة |

## 3. تعريف P1

P1 تبدأ بعد استقرار MVP في الإنتاج، وتضيف:

- **تشخيص تكيفي** متعدد الجولات بإعادة معايرة خريطة الإتقان.
- **مسارات متفرعة** بشروط إتمام/درجات، وإعادة إصدار شهادات بإصدار جديد مترابط (سلسلة `supersedes`).
- **تقييم مزدوج مستقل** مع تحكيم ثالث عند الخلاف، ومهام جماعية.
- **النموذج التجاري المدفوع**: اشتراكات معلمين ومحافظ عبر بوابة الدفع المشتركة (رهن بقرار OD-1).
- **مزامنة Offline ثنائية** مع كشف وحل تعارضات، واستئناف فيديو عبر الأجهزة.
- **تكاملات أعمق**: استيراد أسئلة بنك الطلاب إلى اختبارات TA بموافقة مراجعة، Analytics موحدة، تقارير مدارس/مناطق، بريد معاملاتي، واجهة إنجليزية LTR.
- **اختبارات أداء واختراق دورية** مؤسسية.

## 4. تعريف P2

P2 تمهّد للتطبيق المستقل وتوسّع المنصة:

- تحويل PWA إلى تطبيق مستقل (TWA/Capacitor — قرار OD-6) مع تشغيل فيديو كامل Offline.
- توصيات ذكية بالذكاء الاصطناعي (مسارات ومحتوى)، وتصحيح مقالي آلي مساعد.
- شارات Open Badges وملف مهني عام قابل للمشاركة، وتقييم أقران.
- لوحات BI قابلة للتخصيص، SCORM/xAPI، SMS.
