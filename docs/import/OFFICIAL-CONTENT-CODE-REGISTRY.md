# مرجع الأكواد الرسمي — TCS-2

مرحلة: SHARED_CURRICULUM_SUBJECT_MAPPING_13C (يستبدل TCS-1 من 13B)

**القاعدة الحاكمة:** أكواد المحتوى **يملكها النظام** (System-owned). موظف المحتوى
لا ينشئ كوداً يدوياً ولا يعدّل كوداً موجوداً.

**التغيير الجوهري في TCS-2:** الكود = **الهوية**، والمسار = **التوفّر**.
الكود لم يعد يحتوي على المسار، والمادة المشتركة بين صنعاء وعدن (مثل الفيزياء)
تُدخل **مرة واحدة** ويُحدَّد توفّرها عبر عمود `track_codes`.

## من أين تأتي الأكواد؟

من «مركز الاستيراد» → قسم **قالب جاهز بأكواد النظام**:

1. اختر: الصف ← المسار/المسارات ← (المادة ← الوحدة عند الحاجة).
2. اختر القالب وعدد الصفوف.
3. نزّل الملف: أعمدة الأكواد والمفاتيح الأب **معبأة مسبقاً**.
4. املأ النص العربي فقط، ثم ارفع الملف في مسار: فحص ← تجهيز ← تنفيذ.

## صيغ الأكواد (TCS-2)

| الكيان | الصيغة | مثال |
|---|---|---|
| مادة | `sub-{gradeShort}-{subjectNo:003}` | `sub-g10-003` |
| مجموعة مواد | `grp-{gradeShort}-{groupNo:02}` | `grp-g10-01` |
| وحدة | `unit-{gradeShort}-{subjectNo:003}-{unitNo:02}` | `unit-g10-003-02` |
| درس | `lesson-{gradeShort}-{subjectNo:003}-{lessonNo:003}` | `lesson-g10-003-004` |
| شرح | `exp-…-{lessonNo:003}-{seq:02}` | `exp-g10-003-004-01` |
| مورد | `res-…-{lessonNo:003}-{seq:02}` | `res-g10-003-004-01` |
| تقييم | `asm-…-{lessonNo:003}-{seq:02}` | `asm-g10-003-004-01` |
| سؤال | `q-{gradeShort}-{subjectNo:003}-{questionNo:05}` | `q-g10-003-00007` |

## التوفّر عبر المسارات

- في قالب المواد `01_subjects_template.xlsx` يوجد عمود **`track_codes`**
  (بدل `track_code` القديم) ويقبل أكثر من مسار مفصولة بـ `|`، مثل `sanaa|aden`.
- كل قيمة تُترجم إلى صف في `public.subject_curriculum_tracks`.
- الاستيراد **يضيف** الارتباطات ولا يحذف ارتباطاً قائماً (Additive Sync).
- مادة بلا أي ارتباط مسار: **لا تظهر لأي طالب** ولا يمكن نشرها.
- الوحدات والدروس والأسئلة ترث التوفّر من المادة — لا يوجد عمود مسار فيها.

## قواعد ثابتة

1. **الكود مستقل عن الاسم**: تغيير الاسم العربي لا يغيّر الكود إطلاقاً.
2. **الكود مستقل عن المسار**: إضافة مسار جديد لمادة قائمة **لا** تُنشئ كوداً جديداً.
3. **الدرس لا يعتمد على الوحدة**: كود الدرس لا يحتوي كود الوحدة، فيمكن نقل الدرس
   بين الوحدات دون فقد هويته أو كسر الأسئلة المرتبطة به.
4. **السؤال لا يعتمد على الدرس**: هوية السؤال ثابتة عبر المراجعات والاستهداف.
5. **مصدر الصف والمسار هو البيانات المرجعية الحقيقية فقط** (`grades.slug`،
   `curriculum_tracks.track_code`) — لا قيم مخترعة.
6. **لا إعادة استخدام**: أي رقم خُصّص لا يُمنح لكيان آخر حتى بعد الحذف.
7. **الترقيم بخانات ثابتة** لضمان الترتيب: 3 خانات للمادة والدرس، خانتان للوحدة
   والتسلسل، 5 خانات للسؤال.

المسار يُستخدم في عمود `track_codes` فقط، ولم يعد جزءاً من أي كود.

## كيف يُحسب الرقم التالي؟

النظام يقرأ الأكواد الموجودة فعلياً (قراءة فقط، بدون أي كتابة)، يستخرج أعلى رقم
داخل النطاق نفسه (الصف + نوع الكيان)، ثم يمنح ما بعده. لا يوجد sequence في قاعدة
البيانات ولا ترحيل مطلوب، ولذلك لا يمكن أن يتعارض التخصيص مع كود قائم.

## الأكواد القديمة (TCS-1)

- صيغة TCS-1 كانت تضع المسار داخل الكود (`sub-g10-aden-003`) وهي الآن **مجمّدة**.
- أي محاولة لإدخال كود بهذه الصيغة تُرفض عند الفحص بالخطأ
  `LEGACY_CODE_SCHEME_NOT_ALLOWED`.
- المحتوى التاريخي لا يُعاد ترميزه تلقائياً؛ يظهر في سجل الأكواد ضمن
  `nonConformingCodes`. TCS-2 يسري على كل ما يُدخَل من الآن فصاعداً.
